# admin-async-feedback—pending/error feedback on Admin writes

Implements #411 (deferred from PR #410's review): the admin moderation row actions fired async `data/admin` writes with no local catch or pending state—a rejected write (offline, a rules denial) gave the admin no feedback and surfaced as an unhandled promise rejection. Every such action now disables while its write is in flight and surfaces a rejected write inline, in the spirit of `SchedulePanel`'s `UnlockNowButton`/`ResnapshotButton`. **No write path changes**—this wraps the exact calls the console already made.

## Contract

- `src/components/admin/AsyncButton.tsx` (new)—the shared affordance: a button that runs an async `onAction`, disables while pending, and on rejection renders an inline `.pill.pill-error` alert (`role="alert"`, default copy "Failed—try again."). The button re-enables after a failure—tapping again retries and clears the pill; success clears everything (including the common case where the row unmounts because the subscription removed it). Presentation props (`className`, `title`, `ariaLabel`, children) pass through, so existing selectors and accessible names are unchanged.
- `failureLabelFor?: (error: unknown) => string | undefined` (#134, `specs/post-sailing-archive.md`)—the one way the pill says something other than the caller's fixed `failureLabel`. A write that refuses for a reason the Admin can ACT on—the moderation delete refused because the Proof still backs a marked square on a closing Event, and since #1275 the Approve and Approve all controls, which pass `approvalFailureLabel` (`src/data/approvalFailure.ts`) so a closed Event, a non-admin or a batch over the 400-row cap shows the callable's own fixed message while contention and internal failures keep the retry copy (the 18+ confirm dialog does the same)—has to name the remedy, and "Failed, try again" is exactly wrong there, because trying again does the same thing. Opt-in per call site, consulted only on rejection, and falling back to `failureLabel` when it returns `undefined`, so no other control's copy changes and a raw Firestore error is never rendered by default.
- `src/components/admin/ReviewQueue.tsx`—every row action runs through `AsyncButton`: Clear reports / Hide / Restore / Delete on report rows (both kinds), Ban author / Unban author (`BanControl`), Approve / Reject / Approve all on approvals, Confirm / Reject on claims. The #558 Spicy checkbox has the same contract in checkbox form: it disables while the correction transaction is pending, catches and reports rejection inline, and restores its prior checked state when the optimistic write fails.
- `src/components/admin/PromptPool.tsx`—Hide / Restore / Delete run through `AsyncButton`. The curated add form keeps its existing `busy` state and now surfaces a rejected add inline ("Didn’t add—try again."), keeping the draft text for a one-tap retry. A rejected inline text save keeps the editor OPEN with the draft intact and an inline alert ("Didn’t save—try again.") instead of silently closing as if committed—one failure state serves both commit paths (the Save button and Enter in the input).
- `src/components/admin/PlayersPanel.tsx`—Unban runs through `AsyncButton`.
- Settings (#1678): `GameSettings` catches claim mode, default theme, photo source, EXIF stripping, AI screen, auto-hide threshold and direct force-adult rejections, disables that setting during its write and shows a fixed inline retry alert. Displayed values continue to follow the committed private Event observation, including during optimistic pending echoes. The real 18+ confirm keeps ownership of deferred force-adult failures and retries; cancelling performs no write. `SchedulePanel` applies the same feedback to a Day theme without changing the unlock lock. Local feedback retires when the enclosing private Admin scope unmounts.
- `EasyMixSlider` accepts a synchronous or Promise-returning callback. It dedups pending repeat releases against the latest request while preserving independent rapid keyboard releases. A rejected latest release shows a fixed retry alert, restores its thumb to the committed React prop value only if no input draft revision has occurred since that release, and resets dedup so an identical adjustment retries. A newer draft remains intact even when it leaves and returns to the failed release’s numeric value, and an earlier rejection cannot undo a later release. A layout-phase observation excludes discarded React renders from that fallback without a passive-effect delay. The slider's focused echo guard and blur path stay in force.
- `src/index.css`—`.pill-error`, the failure accent on the existing `.pill` chrome.

## Acceptance criteria

- Given a moderation write that rejects, the acting control shows an inline `role="alert"` failure pill and the promise never escapes unhandled; tapping the control again retries and clears the pill.
- Given a moderation write in flight, its control is disabled—a double-tap cannot fire the write twice.
- Given a rejected inline prompt-text save, the editor stays open with the draft intact.
- Given a successful write, no residual pending or error state remains.
