# The edge Event router (`event-router`)

Implements the edge half of [ADR 0009](../docs/adr/0009-event-resolved-from-hostname.md) for epic #529: one versioned Cloudflare Worker on `*.fiveacross.app` and `*.vacaybingo.com`, so a new Event needs no DNS record, no Hosting custom domain, no certificate and no Worker route of its own. `specs/hostnames-lookup.md` owns the collection this reads; `specs/event-resolution.md` owns the client that reads the same collection after the router has let the request through. The service lives in [`worker/`](../worker/README.md).

## Glossary

**Namespace guard**—the decision, made from the hostname alone and before any data is read, about whether an address may reach the router at all. Distinct from Resolution, which asks whether the Event at a permitted address is servable. *Avoid:* routing rule, hostname check.

**Reserved label**—an infrastructure first label that is never dealt to an Event on any Namespace: `www`, `auth`, `api`, `admin`, `play`, `status`, `d`. *Avoid:* blocked slug (they are not refused because they are bad, but because they belong to something else).

**Fail closed**—answering an Event-not-found *rendered state* for every address that is not an explicit, active, well-formed, address-matching record. Never an exception, and never an inferred active. *Avoid:* 404, error (both understate that the state is drawn).

## Contract

- **The Worker is a router and a namespace guard, never an authorization layer.** The application still verifies membership before reading Event data, and nothing here is load-bearing for that. The router carries the Firebase **web** api key and no service-account credential, so it can read exactly what a browser standing on the same address can read; `firestore.rules` enforces that boundary rather than a promise this code makes about itself. A router holding admin credentials would be one refactor away from becoming the authority ADR 0009 explicitly rejected ("Worker injects the Event ID into the served HTML—rejected: it makes the Worker an authority rather than a router").
- **The Worker is not a canonicaliser, and this is a regression guard rather than an omission.** #599 as amended removed edge canonicalization: every registered host serves in place, and a serving domain is never bounced off itself. No code path in `worker/` constructs a redirect; the origin's own 3xx is passed through untouched (`redirect: 'manual'`) rather than followed, so a followed redirect can never silently land a guest on the origin host. Per-origin sessions, installed PWAs and offline storage are the accepted consequence, not a defect (`CONTEXT.md` § Alias).
- **The serving set is two apexes and their wildcards**: `fiveacross.app` (canonical) and `vacaybingo.com`. `fiveacrossbingo.com` is deliberately not a Namespace—no Event has ever been dealt from that origin, and the whole zone becomes a 301 redirect once #600 completes (#630). Routing a retired brand name through the Event router would keep alive an origin whose purpose is to stop existing.
- **The guard is decided before any data is read**, and that ordering is the property, not an implementation detail: it means no `hostnames/{host}` document—however it came to be written—can publish an Event on a reserved label. Data cannot promote itself past the guard.
- **The Slug contract is one module with two consumers** (`src/slug.ts`): the guard here, and the Event-setup wizard's address step (#790). A label the wizard lets an organizer claim but the router refuses is an Event that provisions successfully and then fails closed forever; a label the router admits but the wizard forbids is an infrastructure name an operator can never take back. The reserved check runs **before** the length checks, so the guarantee rests on the reserved list rather than on `SLUG_MIN_LENGTH` happening to exceed the length of `d`.
- **`status` must be explicit, on the network path and the cache path alike.** Only `active` is servable. A missing or unrecognised value is not treated as active, for the reason ADR 0009 gives: defaulting it would let a half-written routing document publish an Event before the record opts in.
- **The denormalised `slug` is cross-checked.** `specs/hostnames-lookup.md` puts `slug` on the document expressly "for the edge router"; this is that router, and comparing it against the address's first label is what makes a repointed or half-written document fail closed instead of serving. A document with no `slug` fails closed rather than skipping the check. The Namespace **apex** is exempt, because it has no first label and its document's `slug` names the Event's wildcard address rather than this one.
- **Only SERVABLE resolutions are cached**, which is a stronger rule than "only resolutions whose document exists". A cached negative would make a newly provisioned Event unreachable for the length of the TTL—an organizer finishes the wizard, types their own address, and gets the not-found page—which is the moment the product can least afford it. Caching a record that *exists* but does not serve reproduces exactly that defect one step further in: provisioning that briefly exposes a partial document would pin its own failure for a full TTL after the document was corrected. So the decision table runs first and only a `serve` is written. The other half of the same rule is that a non-serving answer **drops** any entry already held, so an Event that goes inactive cannot leave a servable envelope behind for the stale-serve path to resurrect. The not-found response is itself `no-store` for the same family of reasons. A negative lookup is one Firestore point read; volumetric abuse belongs to the Cloudflare layer in front of this code, not to a negative cache inside it.
- **A cached envelope is validated, not merely version-checked.** The cache is a deserialisation boundary—JSON out of a shared store, possibly written by another deployment—so every field the resolver dereferences is checked before it is read. A version check alone would let a current-version envelope carrying a partial `record` reach the decision table and throw on `record.status`, which is the same crash-instead-of-fail-closed failure an unbound binding caused: a Worker runtime error in place of the rendered fail-closed page. Anything that does not conform reads as a MISS, never as coerced data.
- **Freshness requires a non-negative age, not merely an age under the TTL.** An envelope stamped in the future—by a clock-skewed writer, or left by another deployment on the shared cache this module treats as untrusted—yields a negative age that satisfies a bare `< ttl` test, pinning an obsolete mapping for the cache's whole retention window without ever revalidating. A stamp we cannot have written is evidence of nothing.
- **Overlapping lookups are NOT ordered against each other, and that is a decision with a stated bound.** Two lookups can finish out of order, so a positive write from an earlier lookup can land after a later one refused the host and deleted the entry, repopulating a mapping that is disabled or gone. A durable high-water "fence" was implemented to prevent this and then removed: it cannot be correct on the Cache API's primitives, because the fence update is read / `Math.max` / write with no compare-and-set (two concurrent drops can regress it), and because the ordering token was each lookup's start time, which orders *requests* rather than the *document states* they observed. The residual exposure is that a disabled Event may keep serving for about one `cacheTtlMs` — the same staleness the TTL grants by existing — while the client caches the identical mapping for twelve hours (`specs/event-resolution.md`), two orders of magnitude longer. A correct fence needs a compare-and-set store or a server-issued document generation (Durable Objects, KV), and belongs in a change that can justify that dependency rather than being smuggled in as cache bookkeeping. An urgent takedown needs a cache purge and is not made safe by an unsound fence.
- **A deletion is awaited; a write need not be.** `resolveHost` awaits `drop` so a mapping revalidated away cannot be resurrected by a concurrent request whose own revalidation fails, and an adapter that hands the deletion to `waitUntil` and resolves immediately makes that await mean nothing. A write only benefits the next request and may lag; a deletion is a correctness barrier for requests already in flight.
- **A numeric binding is accepted only if the whole trimmed value is digits.** `Number.parseInt` takes a valid prefix and discards the rest, so `750.5` and `2000ms` would be silently honoured as values nobody wrote—and `1e3` would become a **one-millisecond** lookup timeout that fails closed on every uncached host while the binding reads as if it said one second.
- **A DNS root dot is rejected before any routing lookup, despite naming the same resource.** `bodega-bay.fiveacross.app.` serializes as a distinct browser origin, so serving its shell would put its auth helper on an origin that cannot safely be treated as equal to `bodega-bay.fiveacross.app`. The router and browser bootstrap both refuse it before lookup, including a direct-Hosting rollback path; `hostnameKey` remains a storage-key normalizer, never an origin-equivalence predicate.
- **The cache is an optimisation, so every access degrades to "no cache" rather than propagating.** A rejecting Cache API must cost an extra Firestore read, never the rendered fail-closed state and its diagnostic headers—the same rule `specs/event-resolution.md` gives the client, where "storage that throws on access degrades to 'no cache', never to a failed boot."
- **Revalidation failure serves stale, without restamping.** A stale-but-active entry still serves when the lookup cannot be completed, mirroring `specs/event-resolution.md`: an expired mapping beats a dead app when the network is gone, but it stops counting as evidence the mapping is still good, because a bound that renews itself is not a bound. With no entry at all there is nothing to fall back to and the request fails closed.
- **A mapping that is gone is dropped, not expired**, so the edge stops serving it immediately rather than at the end of its TTL.
- **`/__/auth/*` passes through intact, and skips the lookup on purpose.** The namespace guard still applies, so a reserved label's auth path is refused like any other request to it. What the exemption buys is that a transient `hostnames/{host}` failure cannot break the sign-in round-trip on a host that is perfectly valid—the OAuth redirect leg is the worst possible place to add a dependency, because a guest hits it mid-transaction. The surface it opens grants nothing: those paths serve Firebase Hosting's own helper, carry no Event data, and Google matches `redirect_uri` exactly against a registration this router cannot create ([ADR 0010](../docs/adr/0010-centralised-auth-origin-with-handoff.md)).
- **An unconfigured router fails closed for every request, and that check precedes the auth exemption.** A missing api key or project id is not the transient dependency failure the exemption exists to survive—it is total, and a router that half-serves under a misconfiguration is harder to diagnose than one that serves nothing. The exempt path is the one where a silent success would be hardest to notice, which is precisely why it is not exempt from this.
- **The proxy rewrites the Host by rewriting the URL**, because on Workers the outbound Host derives from the request URL and a `Host` header set would be ignored—quietly, which is the dangerous kind. The public hostname stays in the browser because this is a subrequest whose body is returned, not a `Location` that is emitted, and it is forwarded to the origin as `x-forwarded-host` because the origin serves one bundle to every address and cannot otherwise recover it.
- **The not-found state is rendered, dependency-free, and brand-neutral.** It is reached precisely when the router does not know which Event—and therefore which Edition—the address belongs to, so any wordmark it drew would be a guess, and showing a guest the wrong product's name on a dead address is worse than showing them none. It fetches no font, script, image or stylesheet, because it renders when the origin is not being contacted and anything it fetched would be a second way for it to fail. The hostname is not reflected into the markup, so there is no reflection sink to escape wrongly.
- **A refused lookup is reported distinctly from an unreachable one.** Firestore answering 401/403 — the expected shape of App Check enforcement against a caller that holds only the web api key — yields `lookup-forbidden` rather than `lookup-unavailable`. The two demand opposite operator responses: an unavailable dependency is usually transient and self-heals, whereas a refusal is a standing configuration fact that never self-heals and takes every uncached host down as the cache drains. Collapsing them would turn a diagnosable misconfiguration into a mystery outage discovered a day after cutover. A stale servable entry is still preferred over either.
- **Every response carries `x-event-router`; every fail-closed response also carries `x-event-router-reason`** from a closed set. That is what lets an operator tell, from outside, whether the Worker is in front of a host yet and why an address is refused—the question the cutover ladder asks. A malformed first label qualifies its reason with the specific Slug rule it broke, as `invalid-slug:too-short`—qualified rather than replaced, so the class stays greppable as a prefix while the rule is still named, and so `too-short` is distinguishable from `reserved-tag` from outside during a cutover. Both halves come from closed unions, so nothing caller-controlled reaches a response header.
- **Every platform seam is injected** (`fetch`, `cache`, `now`), mirroring the convention `specs/event-resolution.md` sets for the client resolver, so the whole decision table is provable without workerd, Firestore or a network. `worker/src/index.ts` is the only file that imports a Cloudflare type.
- **An unbound binding is normalised to `''`, never left `undefined`.** "Deployed but not yet configured" is a state the cutover procedure deliberately passes through — `wrangler.toml` does not commit `FIREBASE_API_KEY`, which is set separately with `wrangler secret put` — so it is a state the router must ANSWER rather than crash in. A binding typed `string` while the runtime supplies `undefined` is a lie the type checker cannot catch, and the first `.length` read on it throws a Worker runtime error instead of rendering the documented fail-closed response. `worker/src/config.ts` owns that normalisation and is a separate module precisely so a promise about misconfiguration is not made only in code that the real runtime alone can execute.
- **A `*.workers.dev` address is out of Namespace, and that constrains how the router is verified.** Refusing it is correct — it belongs to no Namespace this router guards — but it has an operational consequence: a request dispatched to the workers.dev address carries that hostname in `request.url`, and a `Host` override does not change it, so the deployed-but-unrouted Worker cannot be smoke-tested by curling workers.dev. `wrangler dev --remote` is the rehearsal path instead: it runs this code on Cloudflare's network with real bindings, cache, Firestore and origin, while deriving the URL from the `Host` header sent to `localhost`. A test-only host override is deliberately NOT compiled into the router—a bypass in a namespace guard is exactly the thing a namespace guard exists to not have.
- **Publishing goes through a guarded wrapper, which pins the source AND the toolchain.** `wrangler` uploads the caller's working directory rather than `origin/main`, and once the routes are attached this Worker fronts every wildcard Event hostname, so an unguarded deploy from a feature branch or a dirty tree would replace the router for every Event at once with unreviewed code. `scripts/worker-deploy.sh` and `scripts/deploy.sh` call the same three guards—on `main`, exactly matching `origin/main`, clean working tree—so an operator meets one policy rather than two. `--force` is deliberately limited to the branch/freshness checks; a dirty tree requires the separately auditable `DEPLOY_ALLOW_DIRTY=1` escape hatch. It then installs with `npm ci --include=dev` against a committed `worker/package-lock.json`, never `npm install`, before any Wrangler command—including the route-bearing pre-publish secret check. Explicit dev inclusion is required because Wrangler is a devDependency and an operator's `NODE_ENV=production` or `NPM_CONFIG_OMIT=dev` must not remove the pinned executable immediately before that privileged check. Re-resolving wrangler's caret range at deploy time would let an operator start from the required clean, reviewed commit and still publish or verify through a toolchain nobody reviewed—the guards verifying the source while the toolchain slipped underneath them.
- **A wildcard Worker route is not a wildcard DNS record, and the cutover must exclude the reserved labels explicitly.** Exact DNS records outrank wildcard DNS records, but a Worker route pattern matches every *proxied* hostname in the zone regardless — so `*.fiveacross.app/*` captures orange-clouded reserved labels like the PostHog ingest proxy and the auth host, which this router then correctly refuses, planting a 404 in front of live infrastructure. The `host.ts` guard cannot prevent it: once a route matches, the request belongs to this Worker. Each reserved label must therefore be DNS-only or carry a more-specific "no script" route before the wildcards are attached.
- **The deployed artifact's verification fails closed in all three of its failure modes.** The binding name is compared for exact equality (a substring match accepts `OLD_FIREBASE_API_KEY` and reports green while the real binding is absent); an uninspectable Worker is a FAILED verification rather than a skipped one (exiting zero with a warning lets automation record an unverified deploy as verified); and on a route-bearing deploy the check runs before publishing as well as after, because a route-bearing deploy that fails verification afterwards has already changed live traffic. The deploy wrapper also stops claiming routes are unattached when they are.
- **The deployed artifact's configuration is verified separately from the code rehearsal**, because neither of the other paths can do it: `wrangler dev --remote` uploads the local checkout into a temporary preview with its own local variables and can pass while production has no `FIREBASE_API_KEY`, and the `workers.dev` URL is refused as out-of-namespace before configuration is consulted. The guarded deploy therefore checks the deployed Worker's secret bindings by name and fails closed when the key is absent, so a missing binding surfaces at deploy time rather than as every hostname failing closed after cutover.
- **The service ships deployable but unrouted.** `wrangler.toml` carries its `routes` commented out: attaching them *is* the cutover, the cutover depends on the human DNS work in #539 and the PRD Gate ladder, and it must not be something a deploy command can do by accident.

## Acceptance criteria

- **Given** a hostname under a served Namespace whose first label is a valid Slug and whose record is active and address-matching, **when** a request arrives, **then** it is proxied to the Firebase Hosting origin with a rewritten Host header and the public hostname is unchanged in the browser.
- **Given** the same Event reached on its other registered host, **when** a request arrives, **then** it is served in place with no redirect emitted—on that host or any other.
- **Given** a redirect returned by the origin, **when** the router relays it, **then** it is passed through unfollowed rather than resolved on the guest's behalf.
- **Given** a reserved infrastructure label, **when** a request arrives, **then** it fails closed **without** the lookup being consulted—including when a `hostnames/{host}` document exists for that address.
- **Given** a hostname outside every served Namespace, or one with more than one label above the apex, **when** a request arrives, **then** it fails closed. A Namespace is matched at a label boundary, so a hostname that merely ends with a Namespace's characters is refused.
- **Given** a first label that breaks the Slug contract—too short, edge hyphen, non-LDH characters, or the reserved `??--` tag position—**when** a request arrives, **then** it fails closed with the rule it broke named in the reason header.
- **Given** an unknown, disabled, archived, status-less, `eventId`-less, `slug`-less or slug-mismatched record, **when** a request arrives, **then** it fails closed with a rendered Event-not-found state, and the origin is never contacted.
- **Given** a Namespace apex with an active record, **when** a request arrives, **then** it serves without a Slug cross-check.
- **Given** a fresh cached resolution, **when** a request arrives, **then** it serves with no lookup at all; **given** a stale one and a reachable Firestore, **then** it revalidates and restamps; **given** a stale one and an unreachable Firestore, **then** it serves stale and is **not** restamped.
- **Given** an unreachable Firestore and no cached entry, **when** a request arrives, **then** it fails closed with `lookup-unavailable`—never an inferred active.
- **Given** an unconfigured router (no api key, project id, or origin host), **when** any request arrives—**including** one to `/__/auth/*`—**then** it fails closed rather than serving, and no lookup is attempted.
- **Given** a Worker whose bindings are entirely **unbound** rather than empty—the state between deploying and setting the secret—**when** any request arrives, **then** it renders the same fail-closed response rather than throwing a runtime error.
- **Given** an address that resolved as unknown, **when** its routing document is created and the address is requested again, **then** it serves—no negative was cached and the not-found response was `no-store`.
- **Given** a routing document that exists but does not serve (inactive, malformed, slug-mismatched), **when** it is read, **then** nothing is cached for that host; **given** a host with a servable entry already cached, **when** a read shows it inactive, **then** that entry is dropped.
- **Given** a cache that throws on read, write or delete, **when** a request arrives, **then** resolution continues as a cache miss and the request is answered normally—never as a Worker runtime error.
- **Given** a cached envelope that carries the current version but a malformed or partial `record`, **when** it is read, **then** it is treated as a miss on both the fresh and the stale-serve paths, rather than being dereferenced.
- **Given** Firestore refusing the lookup with 401 or 403, **when** nothing servable is cached, **then** the response is `lookup-forbidden`; **given** a stale servable entry, **then** it still serves.
- **Given** two overlapping lookups that finish out of order, **when** the earlier one's positive write lands after the later one's refusal, **then** the entry may be repopulated and the mapping is corrected by the next revalidation rather than by an edge ordering guarantee.
- **Given** a cached envelope stamped ahead of the current clock, **when** it is read, **then** it is revalidated rather than served as fresh.
- **Given** a numeric binding whose value is not entirely digits (`1e3`, `750.5`, `2000ms`), **when** the config is built, **then** the documented default is used rather than the parsed prefix.
- **Given** a hostname carrying a trailing root dot, **when** the router receives a request or browser bootstrap begins (including on direct Hosting), **then** it fails closed before lookup rather than serving an app on a distinct browser origin.
- **Given** `/__/auth/*` on a hostname that passes the namespace guard, **when** a request arrives, **then** it is proxied intact with its path and query preserved and without a lookup; **given** the same path on a reserved label, **then** it fails closed.
- **Given** any outcome whatsoever, **when** the response is produced, **then** its status is never in the 3xx range unless the origin's own response was.

## Test coverage

- `src/slug.test.ts`—the shared Slug contract: the reserved set pinned verbatim and exhaustively, each reserved label refused as reserved rather than incidentally as too short, the accept/refuse table with one distinct reason per rule, the `??--` reserved-tag position against a legal hyphen pair elsewhere, and the strict-validator / normalising-helper split.
- `worker/src/host.test.ts` and `src/data/hostnames.test.ts`—the namespace and bootstrap guards: the Namespace list pinned (including the deliberate absence of `fiveacrossbingo.com`), host normalisation (case, port, IPv6 literal) and root-dot rejection before either edge or direct-Hosting lookup, both apexes, both wildcards, every reserved label against every Namespace, nested labels, suffix-boundary matching against look-alike hostnames, and each Slug rejection surfacing its rule.
- `worker/src/resolve.test.ts`—the fail-closed decision table and the cache: every unservable record shape, the explicit-`status` rule on both the network and cache paths, the Firestore 404-is-absent / 5xx-is-unavailable split, the unconfigured-router refusal, the TTL boundary, version drift reading as a miss, stale-serve without restamping, drop-on-removal, drop-on-inactive, existing-but-unservable records never being cached, no negative caching, a throwing cache degrading to a miss, and the request itself (point-get path, field mask, no `Authorization` header, bounded signal).
- `worker/src/config.test.ts`—binding normalisation: bound values carried through, optional numerics and version defaulted, malformed numerics falling back rather than propagating `NaN`, unbound string bindings becoming `''` rather than `undefined`, `isRouterConfigured` refusing each missing field in turn, and an entirely unbound Worker rendering the fail-closed response—on the auth path too—instead of throwing.
- `worker/src/router.test.ts`—the pipeline: proxying on both Namespaces with the Host rewrite and `x-forwarded-host`, method/query/body preservation, origin status and headers relayed with the version stamp, the apex, the no-redirect sweep across every outcome plus origin-redirect passthrough and serve-in-place, reserved labels refused with no lookup at all, each fail-closed reason including the qualified `invalid-slug:<rule>` form, the rendered brand-neutral dependency-free not-found body, `no-store` / `noindex`, the origin never being contacted on a fail-closed path, the `/__/auth/*` exemption together with its guard and its prefix boundary, and the unconfigured router refusing every path including the exempt one.
