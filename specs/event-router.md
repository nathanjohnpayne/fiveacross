# The edge Event router (`event-router`)

> **App Check cutover amendment: the lookup seam is now implemented; the operational gates are not (#888).** [ADR 0014](../docs/adr/0014-app-check-compatible-edge-routing-registry.md) and [`event-router-registry`](event-router-registry.md) replaced the edge lookup seam with a server-published, transactional per-host Durable Object registry. As of [#972](https://github.com/nathanjohnpayne/fiveacross/issues/972) this file and `worker/` describe THAT router: the Firestore REST reader, the Firebase api-key/project bindings and the `caches.default` envelope are gone, and the Worker carries no Firebase runtime credential. What remains open is operational — #971's backfill and #973's R0–R3 evidence, which itself waits on [#44](https://github.com/nathanjohnpayne/fiveacross/issues/44)'s App Check enforcement. Both wildcard/real-host routes remain blocked; only the registry contract's guarded synthetic exact-route manifest may be attached, and only by its operator-run controller. Do not weaken App Check, do not restore the Firestore reader, and do not read this note as deployment authority.

Implements the edge half of [ADR 0009](../docs/adr/0009-event-resolved-from-hostname.md) for epic #529: one versioned Cloudflare Worker on `*.fiveacross.app` and `*.vacaybingo.com`, so a new Event needs no DNS record, no Hosting custom domain, no certificate and no Worker route of its own. `specs/hostnames-lookup.md` owns the canonical collection the browser reads and the registry projects from; `specs/event-resolution.md` owns the client that resolves the Event independently after the router has let the request through; [`event-router-registry`](event-router-registry.md) owns the projection and the binding this router resolves against. The service lives in [`worker/`](../worker/README.md).

## Glossary

**Namespace guard**—the decision, made from the hostname alone and before any data is read, about whether an address may reach the router at all. Distinct from Resolution, which asks whether the Event at a permitted address is servable. *Avoid:* routing rule, hostname check.

**Reserved label**—an infrastructure first label that is never dealt to an Event on any Namespace: `www`, `auth`, `api`, `admin`, `play`, `send`, `status`, `d`. (`send` was added by [#1102](https://github.com/nathanjohnpayne/fiveacross/issues/1102): it carries the Resend return-path MX and SPF for `fiveacross.app`, and because a wildcard does not apply to a name that already exists with any record type (RFC 4592), those explicit records occlude the wildcard for that label.) *Avoid:* blocked slug (they are not refused because they are bad, but because they belong to something else).

**Fail closed**—answering an Event-not-found *rendered state* for every address that is not an explicit, active, well-formed, address-matching record. Never an exception, and never an inferred active. *Avoid:* 404, error (both understate that the state is drawn).

**Installed identity**—the `name` and `short_name` a browser reads out of the manifest FILE when a Player installs the app, and keeps until they uninstall it. Distinct from the document title and the iOS home-screen label, which the app repairs in the DOM after resolution; installed identity cannot be repaired at runtime at all. *Avoid:* branding, app name (both blur the file-at-install-time property that makes this the router's problem).

## Contract

- **The Worker is a router and a namespace guard, never an authorization layer.** The application still verifies membership before reading Event data, and nothing here is load-bearing for that. The router carries **no Firebase credential of any kind** — not a service-account key, and since #972 not the web api key either — and its single dependency is a service binding exposing one method. The ceiling is therefore the shape of that binding rather than a promise this code makes about itself. A router holding admin credentials would be one refactor away from becoming the authority ADR 0009 explicitly rejected ("Worker injects the Event ID into the served HTML—rejected: it makes the Worker an authority rather than a router").
- **The lookup is one point call into a named lookup-only entrypoint, and the binding names it explicitly.** `worker/wrangler.toml` sets `entrypoint = "RegistryLookupEntrypoint"` on its `[[services]]` block. Omitting that line, or writing `default`, binds the registry's default export instead — the signed sync/audit/recovery control plane — so an omission that reads as a formatting detail would hand a public edge Worker the private control surface. It is validated by one shared validator (also used by the private harness), checked by the guarded deploy before it installs or publishes anything, and pinned by a configuration test that rejects the omitted, `default` and wrong-entrypoint forms. The router holds no Durable Object namespace and no list or mutation method: the registry is not a directory, and a point lookup for an already-present hostname is the whole of what a public Worker may ask it.
- **There is no fallback behind the lookup, and the absence is the design.** No Firestore, no KV, no Cache API envelope, no negative cache, no stale-serve. The registry's per-host object is the single transactional owner of acceptance and lookup, so a second cached answer could only ever disagree with it, and a router that keeps serving a mapping the registry has retracted is worse than one that fails closed for the length of an outage. The deliberate cost is that a cold request travels to one object's location and that a registry outage removes the only lookup; the deliberate benefit is that "is this address in service?" has exactly one answer. The whole service call is bounded at 2,000 ms and every failure closes.
- **The router serves the exact `GET /.well-known/fiveacross-path-capability` projection from that same lookup.** `{schemaVersion, pathNamespace, revision}`, `Cache-Control: no-store`, and nothing else — no Event id, no Slug, no hostname catalogue, because the endpoint is public and unauthenticated and every additional field would be an enumeration surface. It is gated on the resolution, so a missing, malformed, inactive or tombstoned host returns the fail-closed state and no capability at all. The match is exact in both dimensions: a sibling `/.well-known/…` path and any method other than `GET` fall through to the ordinary pipeline.
- **The two closed rehearsal label classes are addressable, while the whole `r2-` prefix stays unclaimable.** `r2-<26 lowercase base32>` and `r2-root-<20 lowercase base32>` are routed under either Namespace; every other `r2-` label is refused as `reserved-label`, and `validateSlug` refuses the entire prefix so no organizer can ever claim one. Addressable is not servable: a rehearsal host with no committed projection still fails closed as `unknown-host`, and only the guarded controller can create one, because every ordinary claim and mutation path rejects the prefix globally. The exception exists because the guarded synthetic exact routes are the only real-Namespace surface the cutover evidence can be measured on.
- **The Worker answers `/manifest.webmanifest` itself, and that and the path capability are the ONLY bodies it constructs besides the fail-closed page.** `name` / `short_name` are read from the manifest FILE at install time, so a bundle that serves many Editions cannot bake them and the app deliberately does not patch them at runtime either—rewriting the manifest client-side would strand an installed app with an identity no server can later correct (`specs/event-resolution.md`). The edge is the only place left. The Edition comes from the committed projection's `edition`—the SAME point lookup that decided the request may proceed, so the identity served at the edge cannot describe a different revision of the mapping than the Event routed to—and per-origin installed apps are the accepted consequence of #599 as amended rather than a defect: each registered host serves in place, so each host is its own installed app, correctly named. The response carries `x-event-router-revision` like every other served response, because § Failure semantics of the registry spec makes that header a property of a resolved edge record rather than of the proxy path.
- **That route sits after the namespace guard AND after resolution, which makes it the opposite of the `/__/auth/*` exemption.** The exemption exists because the sign-in round-trip must survive a lookup failure; the manifest strictly DEPENDS on the resolution it derives from. So a reserved label, an out-of-namespace host, a malformed Slug, an unknown, inactive or tombstoned Event and a projection this build cannot read all fail closed at this address exactly as they do at every other—an address that does not serve an app does not serve an app identity either. Only `GET` and `HEAD` are claimed; any other method on that path is proxied as before, because a branding change may not quietly start refusing methods the router used to relay.
- **`edition` is carried, never routed on, and there is no default-Edition arm at the edge.** The field arrives inside the committed projection rather than by a second read, and the boundary re-validation refuses a projection whose `edition` is not one this build knows as `replica-malformed` before any route sees it—so the manifest route never has to guess, and an installed app is never named for a product the registry did not commit. A fail-closed outcome carries no Edition at all, for the same reason the not-found page is brand-neutral. The shared builder keeps its unknown-Edition fallback for the build-side consumer, whose input is not registry-validated; at the edge that arm is unreachable by construction.
- **One manifest builder, two consumers.** The document is built by a DOM-free, `import.meta`-free module that both `vite.config.ts` and the Worker call, so the file the origin ships and the response the edge serves are the same bytes for the same Edition. A second definition kept in step by review is how a fresh install and an already-installed shell end up disagreeing about an app's name.
- **The manifest is excluded from the service-worker precache, and that exclusion is half the mechanism rather than an optimisation.** `precacheAndRoute` answers a precached URL cache-first, so an edge-served manifest never reaches a client the worker controls; and the precache entry's `revision` is an MD5 of the build-time bytes, so redeploying the same Edition reuses the hash and an already-installed shell never re-fetches it. `vite-plugin-pwa` appended that entry unconditionally, downstream of `globPatterns` (which never matched `.webmanifest`) and downstream of `manifestTransforms` (which Workbox runs BEFORE it appends additional entries), so the exclusion is achieved by taking the manifest away from the plugin entirely and emitting it from the shared builder instead. A build-time guard parses the emitted worker and FAILS the build if the entry returns, because the config does not mention it and `grep` cannot find it—`dist/sw.js` is minified past the point where grep classifies it as binary and reports nothing.
- **The origin serves the manifest `no-cache`, by declaration.** It already did, but only by falling through the `**` catch-all while also happening to miss the immutable `js|css|woff2|png|svg` rule—right posture held up by two absences. `firebase.json` names it explicitly so a later headers edit cannot make an installed app's identity immutable.
- **The Worker is not a canonicaliser, and this is a regression guard rather than an omission.** #599 as amended removed edge canonicalization: every registered host serves in place, and a serving domain is never bounced off itself. No code path in `worker/` constructs a redirect; the origin's own 3xx is passed through untouched (`redirect: 'manual'`) rather than followed, so a followed redirect can never silently land a guest on the origin host. Per-origin sessions, installed PWAs and offline storage are the accepted consequence, not a defect (`CONTEXT.md` § Alias).
- **The serving set is two apexes and their wildcards**: `fiveacross.app` (canonical) and `vacaybingo.com`. `fiveacrossbingo.com` is deliberately not a Namespace—no Event has ever been dealt from that origin, and the whole zone becomes a 301 redirect once #600 completes (#630). Routing a retired brand name through the Event router would keep alive an origin whose purpose is to stop existing.
- **The guard is decided before any data is read**, and that ordering is the property, not an implementation detail: it means no projection—however it came to be committed—can publish an Event on a reserved label. Data cannot promote itself past the guard. Since the guard also precedes the service binding, foreign or malformed traffic creates no registry work at all, so a flood of invalid hostnames cannot instantiate Durable Objects.
- **The Slug contract is one module with two consumers** (`src/slug.ts`): the guard here, and the Event-setup wizard's address step (#790). A label the wizard lets an organizer claim but the router refuses is an Event that provisions successfully and then fails closed forever; a label the router admits but the wizard forbids is an infrastructure name an operator can never take back. The reserved check runs **before** the length checks, so the guarantee rests on the reserved list rather than on `SLUG_MIN_LENGTH` happening to exceed the length of `d`.
- **`status` must be explicit and known.** Only `active` is servable. A missing value is not treated as active, for the reason ADR 0009 gives: defaulting it would let a half-written record publish an Event before it opts in. An *unrecognised* value is refused as `replica-malformed` rather than read as inactive — it is a projection this Worker cannot judge, and inferring either direction from it would be a guess.
- **The denormalised `slug` is cross-checked on a route projection.** `specs/hostnames-lookup.md` puts `slug` on the source document expressly "for the edge router"; the registry copies it, and comparing it against the address's first label is what makes a repointed or half-written projection fail closed instead of serving. A route projection with no `slug` fails closed rather than skipping the check. The Namespace **apex** is exempt because it has no first label, and a **root** projection is exempt because it structurally carries no slug — which is also what lets the labelled `r2-root-*` rehearsal class serve.
- **Nothing is cached, and no negative is manufactured.** There is no edge cache to hold a positive, so there is none to hold a negative either: a newly published address serves on its next request rather than after a TTL, and the not-found response stays `no-store` so an installed shell or a crawler cannot pin one. An unknown host costs one point call into an object that already exists for the hint; volumetric abuse belongs to the Cloudflare layer in front of this code — the wildcard/WAF unique-host-flood control the registry contract requires before any wildcard route is attached — not to a negative cache inside it.
- **The committed projection is re-validated at the service boundary.** The binding crosses two separately deployed Workers, so what comes back is a contract this module did not write, and one field of it (`revision`) is reflected into a response header. The revision must be a canonical positive decimal, and the Edition, path namespace, route status and root marker must each be a member of their closed set; anything else is `replica-malformed`, never coerced. This is not belt-and-braces over the object's own parse — it is what makes a router built against an older projection shape fail closed rather than dereference a field that has since changed meaning.
- **A numeric binding is accepted only if the whole trimmed value is digits.** `Number.parseInt` takes a valid prefix and discards the rest, so `750.5` and `2000ms` would be silently honoured as values nobody wrote—and `1e3` would become a **one-millisecond** lookup timeout that fails closed on every host while the binding reads as if it said one second.
- **A DNS root dot is rejected before any routing lookup, despite naming the same resource.** `bodega-bay.fiveacross.app.` serializes as a distinct browser origin, so serving its shell would put its auth helper on an origin that cannot safely be treated as equal to `bodega-bay.fiveacross.app`. The router and browser bootstrap both refuse it before lookup, including a direct-Hosting rollback path; `hostnameKey` remains a storage-key normalizer, never an origin-equivalence predicate.
- **A rejected or hung lookup is answered, not propagated.** The service call is raced against the configured bound, and both a rejection and a timeout resolve to the same closed answer rather than escaping the handler. An escaping rejection would delegate the response to Cloudflare and lose the version stamp an operator uses to prove this Worker handled the host—the same reason an origin transport failure is caught below.
- **`/__/auth/*` passes through intact, and skips the lookup on purpose.** The namespace guard still applies, so a reserved label's auth path is refused like any other request to it. What the exemption buys is that a transient registry failure cannot break the sign-in round-trip on a host that is perfectly valid—the OAuth redirect leg is the worst possible place to add a dependency, because a guest hits it mid-transaction. The surface it opens grants nothing: those paths serve Firebase Hosting's own helper, carry no Event data, and Google matches `redirect_uri` exactly against a registration this router cannot create ([ADR 0010](../docs/adr/0010-centralised-auth-origin-with-handoff.md)). It resolves no record, so its response carries no `x-event-router-revision`.
- **An unconfigured router fails closed for every request, and that check precedes the auth exemption.** A missing origin host or an unbound registry binding is not the transient dependency failure the exemption exists to survive—it is total, and a router that half-serves under a misconfiguration is harder to diagnose than one that serves nothing. The exempt path is the one where a silent success would be hardest to notice, which is precisely why it is not exempt from this.
- **The proxy rewrites the Host by rewriting the URL**, because on Workers the outbound Host derives from the request URL and a `Host` header set would be ignored—quietly, which is the dangerous kind. The public hostname stays in the browser because this is a subrequest whose body is returned, not a `Location` that is emitted, and it is forwarded to the origin as `x-forwarded-host` because the origin serves one bundle to every address and cannot otherwise recover it.
- **An origin transport failure remains a router-owned response.** If the Hosting fetch rejects because DNS, TLS or the network failed, the Worker returns a generic `502` with `cache-control: no-store` and its `x-event-router` version stamp instead of throwing and delegating an unversioned error page to Cloudflare. The failure is never a redirect, and the response exposes none of the rejected request's diagnostic detail.
- **The not-found state is rendered, dependency-free, and brand-neutral.** It is reached precisely when the router does not know which Event—and therefore which Edition—the address belongs to, so any wordmark it drew would be a guess, and showing a guest the wrong product's name on a dead address is worse than showing them none. It fetches no font, script, image or stylesheet, because it renders when the origin is not being contacted and anything it fetched would be a second way for it to fail. The hostname is not reflected into the markup, so there is no reflection sink to escape wrongly.
- **A malformed replica is reported distinctly from an unreachable one.** A committed projection the object cannot parse, or one this Worker does not support, yields `replica-malformed` rather than `lookup-unavailable`. The two demand opposite operator responses: an unavailable object is usually transient and self-heals, whereas a malformed projection is a standing data fact that alerts, will not heal on a retry, and takes exactly one host down. Collapsing them would turn a diagnosable replica defect into a mystery outage. There is no third class: `lookup-forbidden` was retired with the Firestore reader that produced it, because there is no longer a lookup that can be *refused* rather than merely unavailable.
- **Every response carries `x-event-router`; every fail-closed response also carries `x-event-router-reason`** from a closed set; and every response decided from a resolved record carries `x-event-router-revision`, a validated canonical decimal. Decided from, not served from: a disabled or archived route and a tombstone's `unknown-host` each carry the committed revision they were REFUSED from, because `specs/event-router-registry.md` § Audit and recovery makes that public `{reason, revision}` pair the evidence a recovery lock is cleared with, and a refusal that dropped it would leave exactly those two states unable to clear one. The refusals with no record to attribute — an uninitialized object, an unavailable or malformed lookup, a slug-mismatched or slug-less projection, and every guard that runs before the lookup — carry no revision at all. That is what lets an operator tell, from outside, whether the Worker is in front of a host yet, which projection it served, and why an address is refused—the questions the cutover ladder asks. A malformed first label qualifies its reason with the specific Slug rule it broke, as `invalid-slug:too-short`—qualified rather than replaced, so the class stays greppable as a prefix while the rule is still named. Both halves come from closed unions, and the revision header is deleted before it is set, so neither a caller nor the origin can put a value of its own into a router diagnostic.
- **Every platform seam is injected** (`fetch`, `registry`), mirroring the convention `specs/event-resolution.md` sets for the client resolver, so the whole decision table is provable without workerd, a Durable Object or a network. `worker/src/index.ts` is the only file that imports a Cloudflare type. The two claims a stub cannot make — that the named binding really does deny the registry's default `fetch`, its object namespace and every mutation method, and that a first unknown-host lookup at the fixed location hint does not prevent later publisher admission — are proved separately against a real object under Miniflare.
- **An unbound binding is normalised rather than left `undefined`** — a string binding to `''`, the service binding to `null`. "Deployed but not yet bound" is a state the cutover procedure deliberately passes through, because the registry service is provisioned separately from the router, so it is a state the router must ANSWER rather than crash in. A binding typed non-optional while the runtime supplies `undefined` is a lie the type checker cannot catch, and the first `.length` read or method call on it throws a Worker runtime error instead of rendering the documented fail-closed response. `worker/src/config.ts` owns that normalisation and is a separate module precisely so a promise about misconfiguration is not made only in code that the real runtime alone can execute.
- **A `*.workers.dev` address is out of Namespace, and that constrains how the router is verified.** Refusing it is correct — it belongs to no Namespace this router guards — but it has an operational consequence: a request dispatched to the workers.dev address carries that hostname in `request.url`, and a `Host` override does not change it, so the deployed-but-unrouted Worker cannot be smoke-tested by curling workers.dev. `wrangler dev --remote` is the rehearsal path instead: it runs this code on Cloudflare's network against the real registry service and the real origin, while deriving the URL from the `Host` header sent to `localhost`. A test-only host override is deliberately NOT compiled into the router—a bypass in a namespace guard is exactly the thing a namespace guard exists to not have.
- **Publishing goes through a guarded wrapper, which pins the source AND the toolchain.** `wrangler` uploads the caller's working directory rather than `origin/main`, and once the routes are attached this Worker fronts every wildcard Event hostname, so an unguarded deploy from a feature branch or a dirty tree would replace the router for every Event at once with unreviewed code. `scripts/worker-deploy.sh` and `scripts/deploy.sh` call the same three guards—on `main`, exactly matching `origin/main`, clean working tree—so an operator meets one policy rather than two. `--force` is deliberately limited to the branch/freshness checks; a dirty tree requires the separately auditable `DEPLOY_ALLOW_DIRTY=1` escape hatch. It then installs with `npm ci --include=dev` against a committed `worker/package-lock.json`, never `npm install`, before any Wrangler command—including the route-bearing pre-publish check. Explicit dev inclusion is required because Wrangler is a devDependency and an operator's `NODE_ENV=production` or `NPM_CONFIG_OMIT=dev` must not remove the pinned executable immediately before that privileged check. Re-resolving wrangler's caret range at deploy time would let an operator start from the required clean, reviewed commit and still publish or verify through a toolchain nobody reviewed—the guards verifying the source while the toolchain slipped underneath them.
- **The router cannot be deployed without the registry service it binds to.** Cloudflare rejects an upload whose service binding names a script that does not exist, so provisioning order is enforced by the platform rather than by a runbook step. That is the correct direction: a router that could publish successfully while holding no lookup source would report a clean deploy and answer `lookup-unavailable` on every address.
- **A wildcard Worker route is not a wildcard DNS record, and the cutover must exclude the reserved labels explicitly.** Exact DNS records outrank wildcard DNS records, but a Worker route pattern matches every *proxied* hostname in the zone regardless — so `*.fiveacross.app/*` captures orange-clouded reserved labels like the PostHog ingest proxy and the auth host, which this router then correctly refuses, planting a 404 in front of live infrastructure. The `host.ts` guard cannot prevent it: once a route matches, the request belongs to this Worker. Each reserved label must therefore be DNS-only or carry a more-specific "no script" route before the wildcards are attached.
- **The guarded deploy verifies two different things at two different moments, and both fail closed.** The registry binding travels with the upload, so the committed configuration *is* the deployed configuration and it is checked **before** anything is installed or published: an omitted, `default`, or wrong entrypoint aborts while nothing has changed. The deployed Worker's secret bindings can only be observed on the Worker, so they are checked **after** publishing — and, on a route-bearing deploy, before it too, because a route-bearing deploy that fails verification afterwards has already changed live traffic. An uninspectable Worker is a FAILED verification rather than a skipped one, since exiting zero with a warning lets automation record an unverified deploy as verified. The deploy wrapper also stops claiming routes are unattached when they are.
- **A surviving Firebase credential fails the deploy, which is the inverse of the check it replaced.** The old wrapper required `FIREBASE_API_KEY` to be bound; the current one refuses to finish while it — or any other secret whose name starts with `FIREBASE_` — still is, an anchored prefix match that names every offender and treats an unreadable listing or entry as evidence of nothing. The code no longer reads it, so it grants nothing on its own — it is refused because R0's evidence claim is that the public router carries no Firebase, KV, cache or Durable Object binding at all, and a credential that outlived the code that used it would quietly falsify that claim. The name is compared for exact equality in both directions, so an unrelated `OLD_FIREBASE_API_KEY` neither trips the refusal nor masks a live binding.
- **The service ships deployable but unrouted.** `wrangler.toml` carries its `routes` commented out: attaching them *is* the cutover, the cutover depends on the human DNS work in #539 and the PRD Gate ladder, and it must not be something a deploy command can do by accident.

## Acceptance criteria

- **Given** a hostname under a served Namespace whose first label is a valid Slug and whose record is active and address-matching, **when** a request arrives, **then** it is proxied to the Firebase Hosting origin with a rewritten Host header and the public hostname is unchanged in the browser.
- **Given** the same Event reached on its other registered host, **when** a request arrives, **then** it is served in place with no redirect emitted—on that host or any other.
- **Given** a redirect returned by the origin, **when** the router relays it, **then** it is passed through unfollowed rather than resolved on the guest's behalf.
- **Given** a reserved infrastructure label, **when** a request arrives, **then** it fails closed **without** the registry binding being touched—including when a committed projection exists for that address.
- **Given** a hostname outside every served Namespace, or one with more than one label above the apex, **when** a request arrives, **then** it fails closed. A Namespace is matched at a label boundary, so a hostname that merely ends with a Namespace's characters is refused.
- **Given** a first label that breaks the Slug contract—too short, edge hyphen, non-LDH characters, or the reserved `??--` tag position—**when** a request arrives, **then** it fails closed with the rule it broke named in the reason header.
- **Given** an unknown, tombstoned, disabled, archived, `eventId`-less, `slug`-less or slug-mismatched projection, **when** a request arrives, **then** it fails closed with a rendered Event-not-found state, and the origin is never contacted.
- **Given** a Namespace apex with an active projection, **when** a request arrives, **then** it serves without a Slug cross-check; **given** a `doorway` or `not-found` root projection, **then** it also serves — the marker controls the app's `/` outcome, not whether the edge may serve.
- **Given** a projection whose revision, Edition, path namespace, route status or root marker is outside its closed set, **when** it is resolved, **then** the response is `replica-malformed` rather than a coerced value or an inferred active.
- **Given** an unavailable object, a rejected service call, or one that exceeds the 2,000 ms bound, **when** a request arrives, **then** it fails closed with `lookup-unavailable`—never an inferred active, and never a stale or second-source answer.
- **Given** an unconfigured router (no origin host, or no registry binding), **when** any request arrives—**including** one to `/__/auth/*` or the path-capability path—**then** it fails closed rather than serving, and no lookup is attempted.
- **Given** a Worker whose bindings are entirely **unbound** rather than empty—the state between deploying it and provisioning the registry beside it—**when** any request arrives, **then** it renders the same fail-closed response rather than throwing a runtime error.
- **Given** an address that resolved as unknown, **when** its projection is committed and the address is requested again, **then** it serves—nothing negative was retained and the not-found response was `no-store`.
- **Given** a resolved record, **when** the response is produced, **then** it carries `x-event-router-revision` with that projection's validated decimal revision, overwriting any header of that name from the origin; **given** an `inactive` route or a tombstone, **then** the fail-closed response carries the committed revision it was refused from, so recovery evidence can compare it against committed state; **given** the auth pass-through, an uninitialized object, an unavailable or malformed lookup, a slug-mismatched or slug-less projection, or any guard that precedes the lookup, **then** the header is absent.
- **Given** an exact `GET /.well-known/fiveacross-path-capability` on a serving host, **when** the router answers, **then** the body is exactly `{schemaVersion, pathNamespace, revision}` with `Cache-Control: no-store` and no Event id or catalogue; **given** any fail-closed lookup on that path, **then** no capability is returned; **given** another method or a sibling path, **then** the request is proxied like any other.
- **Given** a numeric binding whose value is not entirely digits (`1e3`, `750.5`, `2000ms`), **when** the config is built, **then** the documented default is used rather than the parsed prefix.
- **Given** a hostname carrying a trailing root dot, **when** the router receives a request or browser bootstrap begins (including on direct Hosting), **then** it fails closed before lookup rather than serving an app on a distinct browser origin.
- **Given** `/__/auth/*` on a hostname that passes the namespace guard, **when** a request arrives, **then** it is proxied intact with its path and query preserved and without a lookup; **given** the same path on a reserved label, **then** it fails closed.
- **Given** a serving or auth-passthrough request whose origin fetch rejects, **when** the router answers, **then** it returns a non-cacheable, non-redirecting `502` carrying `x-event-router`, without exposing the transport error.
- **Given** a host matching either closed rehearsal class, **when** a request arrives, **then** it is addressed and resolved like any other Event host; **given** any other `r2-` label, **then** it fails closed as `reserved-label`; **given** either class offered to `validateSlug`, **then** it is refused as an organizer claim.
- **Given** a consumer bound to `RegistryLookupEntrypoint`, **when** it attempts the registry's default `fetch`, its Durable Object namespace, or any list or mutation method, **then** each is denied by the binding rather than by a check inside the registry.
- **Given** an unknown host looked up before it is published, **when** the publisher subsequently commits revision 1 for it, **then** the address serves—the attacker-first touch places the object at the fixed hint without preventing admission.
- **Given** a serving hostname, **when** `GET /manifest.webmanifest` arrives, **then** the Worker answers it with the resolved Edition's `name` / `short_name`, `no-cache`, the registered `application/manifest+json` media type, the version stamp and the revision stamp, from the same lookup and with the origin never contacted.
- **Given** the same Event reached on its other registered host, **when** each host's manifest is requested, **then** both answer with that Event's Edition—per-origin installed apps, identically named, rather than one host inheriting the other's identity.
- **Given** a committed projection whose `edition` is not one this build knows, **when** the manifest is requested, **then** the address fails closed as `replica-malformed` and no manifest is served—there is no default-Edition arm at the edge.
- **Given** a reserved label, an out-of-namespace host, a malformed Slug, an unknown, inactive or tombstoned Event, or an unconfigured router, **when** `/manifest.webmanifest` is requested, **then** it fails closed exactly as every other path does—the manifest is not an exemption.
- **Given** a request to that path with any method other than `GET` or `HEAD`, **when** the router handles it, **then** it is proxied as before rather than newly refused.
- **Given** a build, **when** the service worker is emitted, **then** `manifest.webmanifest` is absent from its precache list, verified by PARSING the emitted worker; and **given** an emitted worker with no precache entries at all, **then** that is a build failure rather than a silent pass.
- **Given** the built `manifest.webmanifest` and the Worker's response for the same Edition, **when** both are produced, **then** they are byte-identical.
- **Given** any outcome whatsoever, **when** the response is produced, **then** its status is never in the 3xx range unless the origin's own response was, and no request leaves the Worker except the origin proxy.
