# App Check-compatible Event-router registry (`event-router-registry`)

This is the implementation contract for [ADR 0014](../docs/adr/0014-app-check-compatible-edge-routing-registry.md) and issue #888. It replaces only the edge lookup seam in `specs/event-router.md`; `specs/hostnames-lookup.md` remains the browser-facing source contract, and `specs/event-resolution.md` remains the independent client resolution contract. Until the implementation tickets land, the deployed-but-unrouted Worker still carries its Firestore REST reader and **must remain unrouted**.

## Invariants and threat model

1. **App Check is never weakened for the router.** The Worker sends neither an App Check token nor a Firebase request in the target architecture.
2. **The router is not authorization.** A stale or forged routing projection can make a public shell available or unavailable; it cannot mint a Firebase session or bypass App Check, Firestore Rules, Storage Rules, or Event membership. The client never accepts the edge's `eventId` as its own Resolution.
3. **Firestore is canonical; the edge is a projection.** Only the trusted hostname mutation path changes canonical state. No registry-service path writes back to `hostnames/*`; the separately authorized human recovery tool may use the explicit ledger-repair transaction defined below.
4. **The registry is not a directory.** Public traffic can point-get the value for its already-present hostname only. The public router has no Durable Object namespace binding and neither its service binding nor any public endpoint exposes list.
5. **Address states move monotonically.** Normal publication accepts only the exact successor per-host revision. Recovery never lowers the accepted revision. Retries, gaps, older deliveries, and previously signed payloads cannot overwrite a newer state. A deleted address leaves a permanent tombstone and is not reusable.
6. **One transactional store owns acceptance and lookup.** The per-host Durable Object atomically stores the committed projection, revision, recovery lock, and audit history. No KV, Cache API, database, queue acknowledgement, or other external write participates in the accepted state.
7. **Lookup-gated paths fail closed.** Missing bindings, invalid schemas, unsupported versions, unavailable Durable Objects, and unknown/inactive/tombstoned hosts never proxy the origin on a path that consults the registry. The existing namespace-valid `/__/auth/*` pass-through intentionally bypasses lookup and remains separately guarded. There is no stale or Firestore fallback.

The actors considered are an unauthenticated Internet caller, a modified browser client, a bearer-token thief, a compromised publisher runtime, a compromised public-router deployment, and a compromised registry-service deployment. The protected assets are routing integrity/availability, the hostname registry's non-enumeration property, Firestore data, cross-cloud credentials, and bounded platform cost. GCP/Cloudflare account administrators and a compromised Firebase Hosting origin are outside this contract; both already control the served system. Hostnames, Event IDs, Slugs, Editions, statuses, and individual replica revisions are public metadata, not secrets.

## Architecture and ownership

```text
trusted hostname writer
      │ one Firestore transaction
      ├── hostnames/{host}             public point-get source
      └── routerReplicas/{host}        private desired state + revision
                    │ Firestore event, retry enabled
                    ▼
       replica publisher Function      dedicated service identity + KMS signer
                    │ Google OIDC ID token + signed request bytes
                    ▼
       registry service ──────────────► per-host Durable Object
                    ▲                         │ atomic committed projection
                    │                         │ + revision/recovery/audit
public request ─► Event router               │
                    ├── named lookup-only WorkerEntrypoint: lookup(host)
                    └── active + matching ───► Firebase Hosting origin
```

| Surface | May read | May write | Explicitly may not do |
|---|---|---|---|
| Browser/app | one named `hostnames/{host}` under existing rules | no hostname/replica writes | list either registry; read `routerReplicas` |
| Hostname writer | hostname plus its replica ledger | both in one transaction | report success before replica convergence |
| Publisher Function | its event payload, metadata-server ID token, one KMS signing operation | authenticated signed sync request | call Firestore/Admin SDK; export a key; hold a Cloudflare API token |
| Registry service/DO | validated request and one named object's storage | one host's transactional state | read Firestore; bind another store; attach routes; select an origin |
| Public router | one registry `lookup(host)` result after the host guard | nothing | bind/list Durable Objects; call Firestore; accept edge identity as app Resolution |
| Audit operator | Firestore source/ledger list plus authenticated per-host DO state | nothing in audit mode | consume the publisher identity or enumerate through the edge |
| Source/control attestor | one transactionally consistent Firestore source/ledger read and the nonsampled Function/IAM/KMS control readbacks supplied by the human command | derive and sign the exact fresh canonical projection, equal ledger payload, and control observations with a human-only keyless identity/key | invoke recovery; sign a source/ledger mismatch, invented projection, or control claim without the interactive provider reads |
| Recovery operator | one separately attested Firestore source/ledger observation, provider control-plane/log readback, and one compared DO state | lock, monotonic source-attested repair, audit history, and a separately authorized exact-host WAF rule | use the publisher/source-control-attestor identity or key; lower a revision; invent a projection; attach wildcard/real-host routes |
| Regional probe runner | one public response from its configured deployment region | signed observation to the private attestation endpoint | choose its region label; recover state; satisfy more than its one identity slot |

### Google service identity and edge authentication

Use a dedicated runtime service account, provisionally `event-router-replica-publisher@fiveacross.iam.gserviceaccount.com`. It receives only the roles required for a v2 Firestore event receiver/logging plus `cloudkms.cryptoKeyVersions.useToSign` on one dedicated `RSA_SIGN_PKCS1_2048_SHA256` CryptoKey. Cloud KMS does not support IAM policies on an individual CryptoKeyVersion ([Cloud KMS permissions and roles](https://cloud.google.com/kms/docs/reference/permissions-and-roles)), so this CryptoKey is the narrowest real grant boundary. It contains no unrelated versions: only the publisher's current version is enabled at steady state, and only the current plus replacement versions are enabled during the bounded rotation overlap. The account receives **no** `datastore.*`, Firebase Admin, Secret Manager, service-account-key, public-key-viewer, or Cloudflare permission. Control-plane grants needed to attach the identity belong to deployer/service agents, not the runtime principal, and are reported separately in IAM verification.

Cloudflare has no Google credential, so signature verification never calls KMS at runtime. During reviewed provisioning, a separate deployer identity with only `cloudkms.cryptoKeyVersions.viewPublicKey` reads each publisher, recovery, source/control-attestor, and regional-probe signing version through [`getPublicKey`](https://docs.cloud.google.com/kms/docs/reference/rest/v1/projects.locations.keyRings.cryptoKeys.cryptoKeyVersions/getPublicKey). The command requires the exact version name and `RSA_SIGN_PKCS1_2048_SHA256`, verifies `pemCrc32c`, parses the RFC 7468 PEM as DER SubjectPublicKeyInfo, and computes lowercase hex `SHA-256(SPKI DER)`. It commits the exact `{role, subject, epochOrSlot, keyVersion, algorithm, pem, spkiSha256}` into immutable reviewed registry configuration. Public keys are not credentials, but their mapping is integrity-critical: configuration rejects duplicate role/epoch/slot, version, or fingerprint mappings and fails if the PEM reparse does not reproduce the fingerprint. The registry imports only that pinned SPKI into WebCrypto for `RSASSA-PKCS1-v1_5`/SHA-256; no runtime path has OAuth, `getPublicKey`, or a mutable key-discovery endpoint.

For each delivery the Function obtains a Google-signed ID token from the metadata server for one configured audience and sends it as `Authorization: Bearer`. The endpoint verifies `alg=RS256`, a signing key from `https://www.googleapis.com/oauth2/v3/certs`, `iss=https://accounts.google.com`, exact `aud`, `exp`, `iat` no more than 60 seconds in the future, and the configured stable numeric `sub`. Email is diagnostic only. JWKS refresh is single-flight; an unknown `kid` permits one refresh per five-minute cooldown. Refresh failure returns retryable `503`, while a bad token returns generic `401`.

OIDC authenticates the workload but is still a bearer credential, so the Function asks Cloud KMS to sign `v1\nPOST\n<path>\n<issued-at-ms>\n<publisher-epoch>\n<sha256-of-exact-body>` and sends the key-version resource name, canonical positive-decimal publisher epoch, issued-at, and base64 signature in fixed headers. The registry maps each allowed epoch to one exact subject/key-version/algorithm/SPKI-fingerprint record, accepts a signature timestamp within 60 seconds, and verifies the signature with that pinned public key before applying a payload. The private key never leaves KMS. A stolen OIDC token cannot sign altered bytes; an intercepted complete request can replay only the identical revision/epoch. Ordinary rotation provisions and deploys the new public-key record and epoch before the publisher changes versions, overlaps for one maximum token lifetime plus retry window, then removes the old mapping only after audit shows no use. A key-version name whose configured PEM/fingerprint differs, or a signature valid under any other pinned role/epoch, is rejected.

The exact audience is the separately deployed registry service's `workers.dev` origin plus `/__internal/hostname-replicas/v1`; it is immutable deployment configuration on both sides. That service has no wildcard route. Its default export owns the public `fetch` surface and admits only the signed sync, audit, recovery, and regional-probe challenge/attestation paths below. A separately exported named `RegistryLookupEntrypoint extends WorkerEntrypoint` has exactly one public RPC method, `lookup(host)`, and no `fetch` method. The Event router's Wrangler service binding explicitly sets `entrypoint = "RegistryLookupEntrypoint"`; omitting that field or binding the default export fails configuration validation. Cloudflare documents that the optional service-binding [`entrypoint`](https://developers.cloudflare.com/workers/wrangler/configuration/#service-bindings) selects a named export and that `WorkerEntrypoint` methods form the bound [RPC API](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/rpc/). The Event router's own `workers.dev` behavior remains out-of-Namespace and is never treated as public data-plane evidence. Local tests inject token/signature acquisition and verification; no test key or bypass compiles into production.

## Data and mutation contract

`routerReplicas/{host}` is denied to every Firebase client (`get`, `list`, and all writes). It persists after hostname deletion and has exactly:

```ts
type RouterReplicaDesired = {
  schemaVersion: 1;
  revision: string; // canonical positive decimal, no leading zeroes; compare as BigInt
  host: string;     // hostnameKey(host), identical to the document ID
  desired:
    | { kind: 'route'; eventId: string; status: 'active' | 'disabled' | 'archived'; slug: string; edition: Edition; pathNamespace: 'fiveacross.app' | 'vacaybingo.com' | null }
    | { kind: 'root'; root: 'doorway' | 'not-found'; edition: Edition; pathNamespace: 'fiveacross.app' | 'vacaybingo.com' | null }
    | { kind: 'tombstone' };
  updatedAt: Timestamp; // observability only; never orders writes
};
```

The sync request is `POST /__internal/hostname-replicas/v1`, exact `application/json`, at most 2 KiB, and contains the four fields above with `updatedAt` encoded as RFC 3339. Extra/missing fields, a non-canonical hostname/revision, an unknown status/version/Edition/root/path namespace, a reserved or invalid label, a route whose `slug` does not equal the host's first label (Namespace apex exception preserved), an invalid body signature, and any non-POST method fail before storage. `pathNamespace` is explicit null or one of the two namespace apexes and is valid only on the matching Namespace apex/brand mirror, never an Event subdomain or GCB host. Root shape is valid only on the apex/mirror classes defined by `specs/path-addressing-and-root.md`, except for the controller-only synthetic root-test class below, and forbids `eventId`, `status`, and `slug`. A root-test host must match `r2-root-<20 lowercase base32>.<Namespace>`, carry `pathNamespace:null`, and be transactionally created from its permanent `routerRehearsals/{host}` reservation by the controller; all ordinary claim/mutation paths globally reject the `r2-`/`r2-root-` prefixes. Validation reuses the router's Namespace, Slug, and Edition modules. `edition`, root shape, and capability are copied because #546 and the accepted path-addressing spec must render per-host identity and `/.well-known/fiveacross-path-capability` without another lookup. `adultContent`, `canonicalHost`, `preview`, `apexPath`, membership, Event data, and any hostname catalogue are not projected.

The projection digest is SHA-256 over the UTF-8 JSON array `[1, revision, host, "route", eventId, status, slug, edition, pathNamespace]`, `[1, revision, host, "root", root, edition, pathNamespace]`, or `[1, revision, host, "tombstone"]`; constructing that array is the only canonicalizer. Explicit JSON `null` prevents absent/capable values from colliding. The Durable Object ID is derived from the normalized hostname and is never exposed to the public router.

The object's transactional state is:

```ts
type RegistryState = {
  committed: null | { revision: string; digest: string; payload: RouterReplicaDesired };
  minimumPublisherEpoch: string; // canonical positive decimal; initialized to 1
  highestAuthenticatedPublisherEpoch: string; // canonical non-negative decimal; max authenticated sync epoch, initialized to 0
  highestQuarantinedPublisherEpoch: string; // canonical non-negative decimal; max epoch fenced by integrity recovery, initialized to 0
  recoveryLock: null | { lockId: string; acquiredAt: string; expectedCommitted: null | { revision: string; digest: string }; operatorSub: string; incidentUrl: string; reason: string };
  recoverySequence: string; // canonical non-negative decimal
};
```

Recovery records live under sequence-addressed keys in the same object's storage rather than in an unbounded array. A transaction that changes committed/lock state increments `recoverySequence` and writes the corresponding record atomically; no path updates or deletes an existing record. Short-lived regional-probe challenges/attestations use a separate key prefix, expire after five minutes, and are consumed atomically by the attestation/recovery action that accepts them; they are evidence inputs, not recovery history.

Normal sync first requires an allowlisted subject/key for the signed epoch and rejects an epoch below `minimumPublisherEpoch`. In one DO-storage transaction it raises `highestAuthenticatedPublisherEpoch` to the maximum authenticated epoch even when the revision is later rejected, then rejects any non-null `recoveryLock` with retryable `503 recovery-locked` or applies this table. “No committed change” below means the route projection/revision is unchanged; the authenticated-epoch high-water may still be the transaction's only state mutation.

| Incoming revision | Payload relation | Result |
|---|---|---|
| lower | any | `200 ignored-stale`; no committed change |
| equal | byte-equivalent canonical payload | `200 replay`; no committed change |
| equal | different payload | `409 revision-conflict`; no committed change; alert |
| exactly current + 1 | valid | atomically commit payload/revision/digest; `200 applied` |
| greater than current + 1 | any | `409 revision-gap`; no committed change; retry/alert |

An uninitialized object accepts revision 1 only. The transaction response is emitted only after storage commit. If the response is lost, retry sees equal state and succeeds as replay. There is no external side effect whose outcome can outlive or contradict that transaction.

## Audit and recovery

The audit command obtains the authoritative hostname set by listing `hostnames` and `routerReplicas` with the existing interactive, Admin-authorized operator credential. It never asks Cloudflare to list. For each known host it calls `GET /__internal/hostname-replicas/v1/<percent-encoded-host>?afterRecoverySequence=<cursor>` with a short-lived ID token impersonating a dedicated keyless audit service account. The registry pins that account's numeric `sub` and an audit-only audience. The cursor is absent/`0` on the first page and otherwise is the preceding response's canonical `nextAfter`; malformed or unknown-ahead cursors return `400`. The response exposes committed revision/digest, minimum/authenticated/quarantined publisher epochs, recovery-lock metadata, lookup outcome, and at most 100 append-only recovery records ordered by sequence. It exposes no route payload, public list, or mutation. `nextAfter` is the last returned sequence only when more records exist; the command follows pages to null.

```ts
type CommittedRef = null | { revision: string; digest: string };
type CanonicalHostnameProjection = { sourceDocumentDigest: string; host: string; desired: RouterReplicaDesired['desired'] };
type SourceAudit = { revision: string; digest: string; observedAt: string; canonicalProjection: CanonicalHostnameProjection; ledgerPayload: RouterReplicaDesired; ledgerDocumentDigest: string; attestorSub: string; attestorKeyVersion: string; attestorKeyFingerprint: string; attestationIssuedAt: string; attestationSignature: string };
type ProbeObservation =
  | { phase: 'blocked-before-worker'; probeNonce: string; observedAt: string; rayId: string; host: string; requestPath: string; expectedStatus: 403; observedStatus: 403; expectedBlockBodyDigest: string; observedBlockBodyDigest: string }
  | { phase: 'canonical-after-unblock'; probeNonce: string; observedAt: string; rayId: string; host: string; requestPath: string; expectedStatus: number; observedStatus: number; expectedReason: null | 'inactive' | 'unknown-host'; observedReason: null | 'inactive' | 'unknown-host'; expectedRevision: string; observedRevision: string; expectedServesOrigin: boolean; observedServesOrigin: boolean; originRequestId: string | null };
type ProviderRequestEvidence = { rayId: string; eventAt: string; verifiedAt: string; edgeColoCode: string; host: string; path: string; queryDigest: string; edgeResponseStatus: number; httpLogResponseDigest: string; firewall: null | { action: 'block'; source: 'firewallcustom'; ruleId: string; ref: string; matchIndex: 0; logResponseDigest: string } };

type KeyAccessReadback = { cryptoKey: string; policyEtag: string; signMembers: string[]; enabledVersions: Array<{ keyVersion: string; algorithm: 'RSA_SIGN_PKCS1_2048_SHA256'; spkiSha256: string }>; responseDigest: string };
type ServiceAccountAccessReadback = { subject: string; policyEtag: string; tokenCreatorMembers: string[]; responseDigest: string };
type AccessDecisionReadback = { principal: string; fullResourceName: string; permission: 'cloudkms.cryptoKeyVersions.useToSign' | 'iam.serviceAccounts.getOpenIdToken' | 'iam.serviceAccounts.getAccessToken'; requestTime: string; overallAccessState: 'CANNOT_ACCESS'; responseDigest: string };
type PublisherControlEvidence = { observedAt: string; quarantinedRuntime: { subject: string; functionRevision: string; responseDigest: string }; replacementRuntime: { subject: string; functionRevision: string; responseDigest: string }; activeEpochMappings: Array<{ epoch: string; subject: string; keyVersion: string; algorithm: 'RSA_SIGN_PKCS1_2048_SHA256'; spkiSha256: string }>; keyAccess: [KeyAccessReadback, KeyAccessReadback]; serviceAccountAccess: [ServiceAccountAccessReadback, ServiceAccountAccessReadback]; quarantinedAccessDecisions: [AccessDecisionReadback, AccessDecisionReadback, AccessDecisionReadback]; attestorSub: string; attestorKeyVersion: string; attestorKeyFingerprint: string; attestationIssuedAt: string; attestationSignature: string };

type RecoveryAction =
  | { kind: 'acquire-lock'; wafEvidence: WafEvidence }
  | { kind: 'apply'; lockId: string; publisherReplacement: PublisherReplacement }
  | { kind: 'clear-lock'; lockId: string; wafRemovedAt: string; probeAttestationIds: [string, string, string]; providerRequests: [ProviderRequestEvidence, ProviderRequestEvidence, ProviderRequestEvidence] }
  | { kind: 'abort-lock'; lockId: string; wafEvidence: WafEvidence };
type RecoveryRequest = { schemaVersion: 1; host: string; expectedCommitted: CommittedRef; sourceAudit: SourceAudit; action: RecoveryAction; incidentUrl: string; reason: string };
```

Recovery uses `POST /__internal/hostname-replicas/v1/recover` with exact `application/json` and the `RecoveryRequest` union above. A different human-impersonated recovery service account, audience, and dedicated KMS signing key authorizes the complete request; the registry verifies it only against that role's pinned version/algorithm/SPKI fingerprint, and the publisher has neither. Independently, the human source-attestor command transactionally reads the raw `hostnames/{host}` and `routerReplicas/{host}` documents with its interactive Admin credential. It strictly derives `CanonicalHostnameProjection` from the current hostname document (absence derives only `tombstone`), recomputes the exact ledger projection digest, and refuses to sign unless canonical host/desired bytes equal the ledger host/desired bytes. A malformed source, missing/malformed ledger, mismatch, or direct partial write must be repaired through the explicit Admin ledger-repair transaction first, followed by a new read transaction; attestation never repairs or blesses drift.

Only after equality holds does the command impersonate the human-only source-attestor service account and ask its separate KMS key to sign `v1\nsource-audit\n<host>\n<revision>\n<digest>\n<observed-at>\n<attestation-issued-at>\n<sha256-of-canonical-source-projection>\n<sha256-of-exact-ledger-payload>\n<source-document-digest>\n<ledger-document-digest>`. The same attestor signs publisher control evidence under the disjoint prefix `v1\npublisher-quarantine\n<observed-at>\n<attestation-issued-at>\n<sha256-of-canonical-control-evidence>`. The registry pins a source-attestor subject/audience plus exact key version/algorithm/SPKI fingerprint distinct from publisher and recovery, verifies its short-lived OIDC token from `X-Source-Attestor-Authorization: Bearer <token>` and each embedded signature against that public key, requires the signed attestation time within 60 seconds, and never persists either token. Thus recovery authority alone cannot mint source or publisher-control evidence.

The complete request body is bounded to 16 KiB before parsing and the recovery signature covers every expected state, action, source/control attestation, provider request record, incident URL, and reason. `sourceAudit` must be no older than five minutes nor future. The registry independently requires its canonical projection and ledger payload to carry the request host, requires their desired bytes to match, and recomputes the ledger payload's revision/digest; a stale or poisoned ledger that differs from the canonical hostname-derived projection is inadmissible. `PublisherControlEvidence` is also at most five minutes old, permits at most 16 active epoch mappings and 16 entries in each nested member/version list, exactly two Function-runtime readbacks, two CryptoKey policy/version readbacks, two service-account policies, and three Policy Troubleshooter decisions, and stores SHA-256 digests of the nonsampled provider API responses. A nonempty HTTPS incident URL and reason are mandatory. Extra/missing fields, the same subject/key used for recovery and attestation, an oversized evidence list, or evidence on the wrong action are rejected.

Public recovery evidence comes only from three pre-provisioned regional probe runners. Each runner has a distinct keyless service identity and dedicated KMS signing key whose exact version/algorithm/SPKI fingerprint maps in immutable registry configuration to exactly one deployment region. It first signs a challenge request to `POST /__internal/hostname-replicas/v1/probe-challenge`; the per-host DO issues a random, one-use `probeNonce` bound to subject, phase, host, expected state, and a five-minute expiry. The runner puts that nonce in the exact public request query, records the response, then within 60 seconds submits the exact signed `ProbeObservation` to `/probe-attest`. The registry derives the configured runner region from the accepted subject/key/fingerprint mapping—no body/header may name it—and stores a random one-use attestation ID with the consumed challenge, observation, subject, key version, fingerprint, and receipt time.

Runner testimony is necessary but is not provider proof. The human recovery command also uses a 1Password-backed, read-only Cloudflare Logs token to query the nonsampled Log Explorer `http_requests` dataset for every Ray ID and, for a blocked phase, the `firewall_events` dataset. [`firewall_events`](https://developers.cloudflare.com/logs/logpush/logpush-job/datasets/zone/firewall_events/) supplies the provider-recorded Ray ID, edge colo, host, time, response status, action, source, rule ID, rule ref, and match index; the [Log Explorer API](https://developers.cloudflare.com/log-explorer/api/) supplies an exact Ray-filtered readback. The command includes the normalized record plus each raw response digest in `ProviderRequestEvidence`; no sampled Security Events/GraphQL result is admissible.

Each Ray-filtered provider query must return exactly one matching request; a reused/colliding Ray ID is rejected and re-probed. The DO pairs that record with its attestation and challenge: Ray ID, host, path/query nonce, status, and freshness must match; provider event/readback times must be no older than five minutes nor future; and exactly three provider-recorded Ray IDs and `edgeColoCode` values must be distinct. A blocked record additionally requires `action=block`, `source=firewallcustom`, the exact active `ruleId`/`ref`, match index 0, and the custom block-response digest observed by the runner. A canonical record requires no firewall event and must match the runner's reason/revision/origin observation. Missing, delayed, duplicate, sampled, or mismatched provider evidence fails closed. Neither the registry runtime nor a probe runner receives the Logs token.

Recovery is a closed state machine, each step requiring the current `lockId`, an exact committed-state compare, the recovery identity/signature, and an atomic history append:

1. **Contain and acquire.** The human command installs an exact-host Cloudflare WAF block with a separate 1Password-backed token limited to `Zone WAF Edit` on the two served zones. It generates a random `blockNonce`, configures the exact rule with a unique `ref` and canonical JSON block body `{"recoveryBlock":"<blockNonce>"}`, then reads back the exact zone/ruleset/rule, enabled `block` action, canonical expression `http.host eq "<normalized-host>"`, ref, and custom-response digest. Three fresh blocked attestations plus three matching provider HTTP/firewall records form `WafEvidence`. The DO recomputes the body digest from the nonce, revalidates the exact rule/response fields, three distinct provider colos/Rays, expected committed state, and source freshness, consumes the IDs, then atomically creates `recoveryLock`. Publisher sync is rejected for the entire lock lifetime. If state changed before acquisition, CAS fails and the operator starts from a new audit.
2. **Apply canonical source.** `apply` retains the lock and may write only the freshly attested `sourceAudit.ledgerPayload` after the canonical-source/ledger equality checks above; the same transaction replaces committed state and appends history. It may repair a different payload at the equal revision or jump to a higher source revision, recording every skipped revision range; it never lowers the high-water mark. If the DO is ahead of Firestore, recovery fails `409 source-behind`: an explicit Admin recovery transaction must first advance `routerReplicas/{host}` beyond the DO revision with the current canonical hostname projection, then a new read transaction and fresh signed audit may apply it. An equal-revision repair or any incident where publisher integrity is not proven requires `publisherReplacement`. The human command obtains nonsampled Cloud Functions v2 runtime/revision readbacks, CryptoKey IAM policies and enabled-version lists, service-account impersonation policies, the registry's active mapping digest, and three [Policy Troubleshooter](https://cloud.google.com/policy-intelligence/docs/reference/policytroubleshooter/rest/v3/iam/troubleshoot) decisions for the quarantined subject against replacement-key signing plus replacement-account ID/access-token creation. It normalizes them into `PublisherControlEvidence` and has the source-attestor sign it.

   The registry verifies the mapping digest against its own active configuration and requires the attested runtime subjects/revisions, key versions, algorithms, SPKI fingerprints, enabled versions, policy etags/members, and raw response digests to agree. The replacement key policy may grant signing only directly to the replacement subject—no quarantined subject, group, domain, or broad principal—and the replacement service-account policy may grant no token-creation path to the quarantined subject or a broad principal. All three access decisions must echo the exact quarantined principal/replacement resource/permission/request time and be `CANNOT_ACCESS`; `UNKNOWN_INFO`, `UNKNOWN_CONDITIONAL`, missing inherited policy visibility, or any grant fails closed. `quarantinedEpochCeiling` must be at least `highestAuthenticatedPublisherEpoch`, `highestQuarantinedPublisherEpoch`, and every active mapping usable through the quarantined runtime/key/fingerprint readback; `nextPublisherEpoch` must be greater and map to the attested replacement subject/key/fingerprint. The same DO transaction applies the source, stores the bounded evidence/history, raises `highestQuarantinedPublisherEpoch` to the ceiling, and raises `minimumPublisherEpoch` to `nextPublisherEpoch`; it does not claim authentication until a replacement sync arrives. A simple missing-delivery jump from an otherwise trusted publisher may send null.
3. **Prove and clear.** Before WAF removal, private audit must show lock held, source = committed, no drift, and any required replacement publisher epoch active while every quarantined-accessible epoch is fenced. The command removes the exact-host rule while the lock still rejects all publisher changes, then obtains three canonical attestations and matching provider HTTP records. A failure reinstalls the WAF rule and keeps the lock. `clear-lock` requires fresh source = committed and atomically validates/consumes three distinct attestations/provider colos/Rays whose host/result/revision equal committed state, appends them, and clears the lock. Queued publisher retries may proceed only afterwards; if Firestore advanced during recovery, the fresh-source compare prevents clear until that revision is applied.
4. **Abort without mutation.** `abort-lock` is allowed only when a fresh source audit exactly equals committed state and new `WafEvidence` independently re-proves the exact rule through three distinct provider colos/Rays. The transaction consumes those attestations, records the provider evidence/reason, and clears the lock without changing committed state or bypassing the monotonic rule, but it does not authorize WAF removal: public traffic stays contained. Returning that host to service requires a new fresh `acquire-lock` followed by the same canonical `clear-lock` evidence path; removing the WAF directly after abort is a contract violation.

The recovery history record includes action (`acquire-lock|apply|clear-lock|abort-lock`), before/after, skipped range, canonical-source and equal-ledger projections plus both document digests and attestor identity/key/fingerprint/signature, bounded publisher Function/IAM/KMS/mapping/fingerprint evidence and raw-response digests, WAF rule/config/provider-log/probe evidence where required, public probe results, recovery-operator subject/key version/fingerprint, incident URL, and reason. It excludes OIDC/API tokens, is append-only, and is paginated. No adaptive analytics or sampled log is an admission source. A compromised publisher cannot invoke recovery; a compromised recovery identity still lacks the independent source-attestor signature needed to write a fresh, non-decreasing projection for one compared host.

## Provisioning, mutation, and deletion

One transaction helper owns every projected hostname mutation. Current `adultContent` derivation may continue updating its non-projected field without a revision. Any mutation of `eventId`, `status`, `slug`, `edition`, `root`, or `pathNamespace`, and any create/delete, must also read the persistent replica ledger, increment its revision, and write the matching desired state in the same transaction. `apexPath` remains target/client resolution data and is deliberately not copied. A direct or partial Admin SDK write is a contract violation caught by audit.

- **Provision:** validate Namespace/Slug/reserved labels; reject any existing hostname or tombstone; create `hostnames/{host}` initially `disabled` and the matching route projection at revision 1. Wait for publisher acceptance and edge inspection before activation.
- **Ordinary update:** non-projected fields do not churn the edge. Status, Edition, root, or path-capability changes produce one new revision. Root/route transitions and capability enablement obey `specs/path-addressing-and-root.md`'s archive transaction and deployment barrier. Active `eventId`/`slug` changes are rejected.
- **Repoint:** active → disabled and converge; change `eventId`/`slug` while disabled and converge; active and converge. Skipping or combining barriers is prohibited. An Edition-only correction need not disable the host, but manifest verification remains part of convergence.
- **Disable/archive:** write inactive state and its revision atomically. Normal completion waits for DO convergence. Immediate withdrawal installs the exact-host WAF block before the source mutation.
- **Delete:** reject active delete. After inactive convergence, atomically delete `hostnames/{host}` and advance `routerReplicas/{host}` to tombstone. Wait for tombstone convergence. Never delete the ledger/DO state or reuse the address.

The first implementation includes a dry-run-by-default backfill/reconciler. It lists with Admin credentials outside the request path, computes the exact projection, creates missing ledgers without changing public documents, and refuses conflicting histories. Its audit mode compares canonical host documents, desired-state ledgers, and per-host DO committed/lock/history state. It emits counts plus host/revision identifiers but no bearer tokens or credential material. There is deliberately no runtime acknowledgement write into Firestore: granting the publisher database write permission merely to record its delivery would undo the IAM narrowing.

## Lookup, cache, and abuse posture

The resolver calls only `RegistryLookupEntrypoint.lookup(host)`. Every sync/lookup/audit/recovery/attestation path derives the same DO ID and calls `getByName` with the immutable v1 deployment constant `locationHint:'wnam'`; no request, hostname, or caller location can alter it. The hint is applied even when an unknown-host lookup is the object's first touch, so an attacker cannot place a future hostname near itself before publisher admission. Changing the hint requires a versioned placement/migration decision rather than ambient geography. The object returns its committed projection; absent state is unknown. The public router receives neither the registry's default `fetch`, DO namespace, nor any list method. From the same result it serves exact `GET /.well-known/fiveacross-path-capability` as `{schemaVersion:1,pathNamespace:'fiveacross.app'|'vacaybingo.com'|null,revision:string}` with `Cache-Control: no-store`; missing/malformed/inactive/tombstone lookup fails closed and returns no capability. Root markers are valid configured origins: `doorway` or `not-found` controls the app's `/` outcome, not whether the edge may serve its shell/capability.

The current `caches.default` envelope is removed and neither service adds application, negative, stale-serve, or Firestore fallback caching. Every accepted lookup is strongly consistent with that object's committed state. The deliberate cost is that a cold global request travels to one object's location; hibernation/reset may add storage-read latency, and a DO outage removes the only lookup. The existing strict digit parser bounds the entire service call at 2,000 ms and every failure closes.

The Namespace/reserved/Slug guard runs before the service binding, so foreign/invalid traffic creates no DO work. A random valid hostname can still instantiate/read an empty object at the fixed hint, so wildcard WAF/rate limits must bound unique-host floods before routes attach. Alerts track lookup count/cardinality, empty-object rate, cold/warm latency by colo, hibernation/reset/error outcomes, CPU/storage requests, and spend. The sync/audit/recovery/probe fetch paths enforce exact route/method/content type and the 2 KiB/16 KiB bounds before JSON/JWT work, use Cloudflare per-IP rate limiting for invalid callers, single-flight cached JWKS, and generic errors. Automated DDoS protection and account spend alerts remain enabled.

Remote evidence needs a real Namespace request path: neither service's `workers.dev` origin qualifies, and waiting for wildcard cutover would make R0–R3 circular. A guarded rehearsal controller therefore owns a bounded exact-route surface, but #970 only builds and privately tests that controller; #972 first authorizes invoking it against the replica-capable Event router, and #973 owns final remote evidence. For each run the controller transactionally reserves at most 64 aggregate hosts in a deny-all `routerRehearsals/{host}` collection. Ordinary synthetic/cold hosts match `r2-<26 lowercase base32>.<Namespace>`; a root-shaped test uses the disjoint globally reserved `r2-root-<20 lowercase base32>.<Namespace>` class. Every ordinary hostname claim globally rejects both prefixes and also checks permanent reservations in its transaction. The controller alone may create a manifest-listed root-test hostname document plus equal replica ledger in the same transaction as its classed reservation; the public router never reads the reservation.

The controller uses a human-only 1Password token scoped to DNS/Workers-route edit on the two zones to create proxied DNS plus an exact `<host>/*` route to the reviewed Event-router script. It refuses an apex, wildcard, non-manifest/non-reserved host, any label outside the two closed classes, a dirty/non-main artifact, or a script version other than the recorded candidate. The signed run manifest records run ID, host class, exact hosts/routes/DNS record IDs, script version/source commit, expected synthetic state, creator, and expiry. It supplies separate hosts for active/inactive/root-test/tombstone/unknown recovery and the 30 never-used cold markers. Before route removal, cleanup transactionally tombstones every synthetic hostname/ledger and waits for DO convergence; it then removes every exact route and synthetic DNS record, verifies provider absence, and alerts until cleanup succeeds. Permanent reservations, replica tombstones, DO state, and recovery history remain. A failed cleanup can expose only manifest-listed, globally reserved synthetic exact hosts, never a real Event, apex, or wildcard. No runtime receives DNS/route credentials, `wrangler.toml` keeps both wildcard blocks commented, and #529 retains exclusive authority for wildcard or real-host attachment.

Cold/warm evidence is executable rather than inferred from a 30-second wait. For each of at least three probe regions, R2 generates ten never-before-used valid synthetic hostnames recorded in the evidence manifest; the first public lookup is the remote cold marker (new fixed-hint object plus first storage read), followed immediately by 20 sequential warm lookups of that same object. Local Miniflare coverage separately disposes/recreates an initialized object isolate to prove committed-state reload after reset; provider eviction timing is never claimed. Across the 30 remote cold markers, cold maximum must be at most 1,500 ms. Across warm samples, p95 must be at most 1,000 ms and maximum at most 1,500 ms. Every lookup must remain under the 2,000 ms router bound with zero wrong results/timeouts. The 24-hour R1 synthetic stream must keep `lookup-unavailable` below 1% with no three consecutive failures; otherwise cutover fails.

## Failure semantics

| Condition | Router/result | Retry/fallback |
|---|---|---|
| uninitialized DO | rendered not-found, `unknown-host` | none; no negative cache |
| valid inactive/tombstone | rendered not-found, `inactive` / `unknown-host` | none |
| malformed/unsupported committed state | rendered not-found, `replica-malformed` | alert; no Firestore |
| Slug mismatch/missing | existing `slug-mismatch` / `slug-missing` | none |
| registry binding absent, or service/DO lookup rejects/times out | rendered not-found, `lookup-unavailable` | alert; no stale/Firestore fallback |
| `/__/auth/*` on configured router | preserve existing lookup bypass/origin pass-through | missing required bindings still fail closed first |
| publisher token/body signature/epoch rejected | sync `401` | Function throws; no state change |
| JWKS unavailable for unknown key | sync `503` | Function throws; platform retry |
| stale/replayed delivery | `200 ignored-stale` / `200 replay` | idempotent success |
| same revision, different payload | sync `409 revision-conflict` | no change; retry plus page |
| future non-successor revision | sync `409 revision-gap` | missing delivery may heal; otherwise recovery |
| publisher while recovery locked | sync `503 recovery-locked` | retry after source-attested recovery clears |
| audit/recovery caller rejected | `401` | no data/state returned; operator reauthenticates |
| recovery CAS/source/monotonic/probe check fails | `409` | no change; repeat source/DO audit and containment |
| origin fetch fails | existing generic `502 origin-unavailable` | unchanged |

Every public response keeps `x-event-router`; fail-closed responses keep a closed `x-event-router-reason`. A resolved edge record carries `x-event-router-revision`, a validated decimal string. No caller-controlled diagnostic enters a header.
