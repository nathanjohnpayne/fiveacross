# Proof-media hold reconciliation (#1524)

The reconciler reads the current Proof, never a trigger's decision payload. Existing active Proofs without `safetyHide == true` want lifted media; absent, pending, flagged, hidden and unknown states want held media. Only the current `storagePath` and its thumbnail can lift; another uploader or extension under the same Proof id remains held. Objects are listed in bounded pages with a server-side Proof-id glob for normal IDs; unsafe glob characters or patterns beyond the API limit fall back to an exact-filtered Event scan. This finds every uploader and extension without trusting deleted document data.

`faSrc` stores Firestore seconds plus nanoseconds losslessly as a fixed-width lexically ordered string (seconds offset from Firestore's minimum date, then nine nanosecond digits). Existing Proofs use their native `updateTime`; missing Proofs use the `readTime` of the same snapshot that observed absence. Strictly older decisions are refused, including within one millisecond. Equal versions may repair different hold state. An already matching decision, including source, token policy and lease cleanup, performs no write. A newer source is recorded even if its hold bit is unchanged so a stale concurrent decision cannot overwrite it.

Every metadata write uses both `ifMetagenerationMatch` and `ifGenerationMatch` to reject replacement objects whose metageneration restarts at the same value; a 412 restarts from the Proof read, bounded to eight attempts before retryable failure. Holds strip download tokens and set private/no-store cache policy in the same write. Authenticated proof-media reads from merged #1532 are the prerequisite for this trigger, so an approval/restore no longer relies on a legacy bearer link. Lifts preserve token state. No bytes move. Objects reconcile independently; a partial lift failure leaves later held objects held. Malformed source versions, leases or generation metadata fail closed.

Live pre-hold leases survive hold-direction writes as well as blocking lifts: clearing a lease on a hold could let an overlapping restore lift before that hide commits. Expired leases are cleared during repair. A blocked lift durably re-enqueues its scope for the lease deadline. A server-only `proofMediaHoldRepairs` collection and a minute scheduler deliver overdue repairs in deadline order. Failed jobs move one minute into the future under revision CAS so they cannot monopolize the page; malformed rows returned by the due query are logged and retired only under their snapshot update-time precondition. Missing/non-numeric deadline rows need the bounded hygiene audit tracked in #1870; they cannot occupy valid due-query slots. Transactional revisions prevent an old worker from deleting a newly scheduled repair. Queue persistence precedes pre-hold object writes, so an aborted hide schedules its own recovery even though it creates no Proof trigger.

Client uploads cannot supply the server-owned `faSrc`, `faHold` or `faLease` metadata keys. The metadata-only rule adds no Firestore read. Deploy this Storage-rule reservation before enabling the reconciler; existing objects with preexisting hold keys need a trusted inventory/reset before the trigger is enabled. `ENABLE_PROOF_MEDIA_HOLD` defaults off and gates both reconciliation endpoint exports at discovery and runtime, using the same project dotenv precedence as the Vision export. Enable it only after that inventory/reset and #1356's cutover. With the hold gate enabled, thumbnail creates start held and use `ifGenerationMatch: 0`; redelivery preserves the existing generation and any live hide lease. Both new and already-existing thumbnails reconcile before the optional Vision gate. Hold-reconciliation and transient source-download failures escape for Storage-event retry. Optional Vision-gate/scan/verdict failures are acknowledged. With the hold gate off, no hold endpoints or thumbnail reconciliation are enabled, and the Vision Storage trigger retains its non-retry behavior.

The hold bit does not yet deny authenticated downloads: the Storage read arm is unchanged here. Before enabling these triggers, #1356 must ship and prove its accepted read rule: admission is required for every caller, then a held object remains readable only to its uploader or an Event Admin. That cutover also owns born-held client uploads and token-recreation staging tests. This module alone does not enforce moderation privacy.

The exported hide pre-hold strips tokens, sets a ten-minute lease and never changes `faSrc`. The exported hide wrapper prepares the Proof commit, refuses to start it at or after the deadline minus a two-minute margin, then pre-holds and prepares again. Future hide callers must put their final bounded (at most 120 seconds) commit in that closure, with no intervening awaited preparation. This ticket exports that safety contract and tests refusal; it does not switch the existing manual, Vision or report hide paths, change the client upload payload, or claim deployed no-gap privacy. Those cutovers and real staging acceptance remain #1356 work. Equal-version repair remains safe only while wanted state depends solely on the Proof snapshot.

Validation: `tests/functions/proof-media-hold.test.ts` covers stale/fresh and equal-version decisions, same-millisecond nanoseconds, delete/readTime/recreate ordering, 412 rereads, token policy, partial failure, aborted-hide repair, live lease preservation, re-enqueue revisions, an overrun refusing its commit, malformed-job isolation, failure backoff, late thumbnails, create-only thumbnail lease preservation, default-off runtime/discovery endpoint gates, optional Vision failure isolation, server-filtered listing, empty-page pagination and unsafe/oversized-ID fallback. Production staging is separate.
