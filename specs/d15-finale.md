# Two-beat finale: last-call standings + freeze + podium (`d15-finale`)

Implements `plans/daily-cards-spec.md` § "Scoring and social surfaces" → "The finale—two-beat finish" and § "Farewell view". The Event ends on two scheduled beats, timed by `finaleTimes` (`d15-scheduler-unlock`, #202): a last-call Moment posts the going-into-the-final-night standings at `lastCallAt`, and at the Event's **Standings Freeze** (`finaleTimes`' `standingsFreezeAt`—the configured `EventDoc.standingsFreezeAt`, else the first ceremonial Day's own `unlockAt`; ADR 0011) the standings **freeze** (`EventDoc.frozenAt` set), the closing Day unlocks, and the finale view opens with the **podium**—Event champion, Event-wide First to BINGO, and the ten daily honors—also posted as a final Moment. In the STANDARD shape those instants are **20:00 on Day 9** and **08:00 on Day 10**; a schedule whose closing Day would otherwise leave an empty last-call window instead derives `lastCallAt` backwards from the close (#784), so this ticket's content functions take the boundary from `finaleTimes` rather than assuming a fixed wall-clock time. `d15-scheduler-unlock` (#202) owns firing the two beats on schedule; this ticket owns their CONTENT—the standings/podium copy and computation—and the client-side farewell podium banner + freeze semantics.

## Contract

- `functions/src/finaleContent.ts` (new, needs-phase-4)—pure, injectable content functions the scheduler's last-call / freeze+podium triggers call into (the STANDARD shape fires those at 20:00-D9 / 08:00-D10; #784's same-date fallback fires last-call earlier, relative to the close, instead). No `firebase-admin`, no live backend (mirrors `unlockDay.ts`'s decoupled-pure posture):
  - `lastCallStandingsCopy(players, opts?)`—the going-into-the-final-night line ("Jess leads by 2 bingos—standings freeze at 8 a.m."), naming the leader and their margin; degrades to a generic line on a tie or an empty board. `opts.freezePhrase` overrides the trailing "standings freeze at …" clause; `DEFAULT_FREEZE_PHRASE` ("standings freeze at 8 a.m") is only the fallback for an Event with no usable freeze instant, never the normal case (#800 — see `freezePhraseForUnlock` below).
  - `freezePhraseForUnlock(freezeAt, timeZone)` (#800)—derives the ACTUAL freeze phrase from the Event's Standings Freeze, formatted in the Event's timezone ("standings freeze at 11 a.m" for an 11:00 freeze, not a hardcoded 8). `runFinaleBeats` (`functions/src/unlockDay.ts`) computes this once per last-call beat, passes it as `lastCallStandingsCopy`'s `opts.freezePhrase`, and persists it on the posted Moment (`lastCall.freezePhrase`) so the client's reconstruction reads the SAME string rather than reformatting the instant itself. Falls back to `DEFAULT_FREEZE_PHRASE` when the instant is missing/non-finite. **Which instant** (#800 shipped before ADR 0011, and the answer changed): it is `times.standingsFreezeAt`, the RESOLVED freeze, not a closing Day's `unlockAt`. Identical for both live Events—Bodega pins the two equal to the millisecond—but load-bearing for an Event that plays competitively until a configured check-out freeze, where no Day's unlock equals the freeze and quoting one would announce the wrong deadline.
  - `normalizeTimezone(raw)` / `DEFAULT_TIMEZONE` (#800 Codex P2)—mirrors `src/data/converters.ts`'s `normalizeTimezone`/`DEFAULT_TIMEZONE` exactly (`Europe/Rome`), restated here because `runFinaleBeats` reads the raw Firestore Event doc directly, bypassing `eventConverter`. A malformed/missing `timezone` must resolve to the SAME zone on both sides, or the freeze phrase reintroduces the very two-rendering-paths-disagree bug #800 exists to close, one layer down.
  - `buildPodiumPayload(players, days, dayHonors)`—the podium payload: Event champion (top of the aggregated standings, EXCLUDING every CEREMONIAL Day), Event-wide First to BINGO (non-Tutorial Days only—a Tutorial Day's mark never takes the honor). Excluded by `DayDef.tutorial` ALONE, never by pool: pool identity and Tutorial framing are independent (ADR 0011), and a curated pool can be real competitive play, and the ten daily honors read from each Day's `meta.firstBingo`.
  - `ceremonialDayIndexes(days)`—the standings exclusion, keyed on each Day's stated Scoring Policy via `scoringForDay` (`functions/src/scoringVocab.ts`), never on its pool (ADR 0011). A SET, not the single index the superseded `farewellDayIndex` returned: a schedule may state as many ceremonial Days as it means, and a competitive final morning states none.
  - The ranking + tutorial-exclusion semantics MIRROR `src/game/logic.ts`'s `comparePlayers` / `eventFirstBingoAt` (the app and functions packages are deliberately decoupled, like `autohide.ts` from `moderation.ts`).
- `src/data/finale.ts` (new)—the client mirror:
  - `buildPodium(players, days, dayMetas?, dayMetasLoaded?, freezeAt?)`—the same podium the scheduler posts, computed client-side from the live `PlayerDoc` aggregates + per-Day honors, AS OF `freezeAt`. The cutoff is load-bearing rather than cosmetic: a ceremonial Day keeps recording Marks after the freeze (its bucket is retained so its own daily honour still renders), so without it a post-freeze bingo on a ceremonial `tutorial: false` Day mints a First to BINGO the scheduler's already-posted, immutable podium Moment does not have—the Card and the Feed naming different winners. `buildPodiumPayload` takes the same parameter so the parity test can feed both post-freeze data. The champion/standings EXCLUDE every ceremonial Day's contribution, so a post-freeze goodbye mark never moves the podium (the podium is "as of `frozenAt`", not live). A schedule with no ceremonial Day excludes nothing, and a Player row with no `dayStats` keeps its root totals—in both cases re-summing the buckets would rewrite a legacy/hybrid row rather than leave it alone.
  - `finaleDayIndex(days, freezeAt)`—the ONE definition of which Day the finale lives on: the LAST Day still open at the Standings Freeze, else `-1`. Read by both the default-view pin and the podium's mount gate in `Board.tsx`, so those cannot disagree. Keyed on the FREEZE rather than on the first ceremonial Day: the two coincide whenever the freeze is derived (a derived freeze IS that Day's unlock), but a schedule with an early ceremonial Day, later competitive Days and an end-of-Event freeze would otherwise strand the podium mid-Event. A Day's Scoring Policy says whether its Marks count; it does not elect the finale's host.
  - `finalePinIndex(days, frozenAt, now)`—the default-view pin: `finaleDayIndex`'s Day once `frozenAt` is set AND that Day is unlocked, else `null` (fall back to the normal "today" default). Never pins before the freeze. Renamed from `farewellPinIndex` (ADR 0011): an Event whose final morning is competitive has no ceremonial card to pin, and falling back to "today" after the Event ends lands on a Day the schedule no longer has.
- `src/lastCallCopy.ts` (new, #800; extracted from `src/components/ProofFeed.tsx`)—`lastCallLineFromPlayers(players, freezePhrase?)`, the client's ban-aware reconstruction of the last-call line: `ProofFeed.tsx` cannot simply display the scheduler's posted `line` string, because a Player banned AFTER the beat posted must still be removable from a still-live leaderboard read, so the Feed re-derives the sentence from the Moment's `lastCall.players`, filtered to exclude any now-banned uid. It takes `moment.lastCall.freezePhrase` as its freeze-phrase argument (falling back to the historical literal only for a legacy Moment posted before #800) rather than an independently hardcoded string, mirroring `lastCallStandingsCopy`'s leader/margin phrasing (a parity test, `tests/functions/lastcall-copy-parity.test.ts`, pins the two together).
- `src/components/FarewellPodium.tsx` (new)—the closing view's podium banner (champion + Event-wide First to BINGO + ten daily-honor rows), rendered ABOVE the goodbye banner (`d15-tutorial-banners` owns the goodbye copy/mount; this ticket owns the podium banner and their stacking order). Issue #449 later added the podium's own share affordance—a "Share final standings" button at the bottom of the section rendering the same frozen `Podium` payload as an on-device Share Card; the card and share mechanics are owned by `specs/w2-share-cards.md` § Final standings.
- `src/components/Board.tsx` (modify)—mount the podium above the goodbye banner on the FINALE Day once frozen (gated on `finaleDayIndex`, not on the viewed Day's pool), and pin that Day as the default view once the Event has ended (`finalePinIndex`).
- `functions/src/unlockDay.ts`—`finaleTimes(days, standingsFreezeAt?)` resolves the beat clock. The freeze/podium anchor is the Event's Standings Freeze: the configured `EventDoc.standingsFreezeAt` when the doc carries a usable one, else the first ceremonial Day's own `unlockAt`—which on both live Events is the closing Day's 08:00, exactly the instant the superseded `pool === 'closing'` lookup produced. `null` when the Event has NEITHER, so callers skip the finale entirely; the finale is a stated freeze or a stated policy, never merely the schedule ending. `podiumDayIndex` is the ceremonial Day when there is one, else the LAST Day, and `lastCallDayIndex` is clamped at 0 so a one-Day schedule cannot file a Moment under Day -1.
- `src/types.ts` / `src/data/converters.ts`—`EventDoc.frozenAt?: number` (ms epoch) is the freeze stamp; a missing field reads as `undefined` (unset) through `eventConverter`'s passthrough. (Landed with the #212 schema contract.) `LastCallMomentPayload.freezePhrase?: string` (#800) is the scheduler's computed freeze phrase, persisted on the `last_call` Moment. `EventDoc.standingsFreezeAt?: number` (ADR 0011) is the CONFIGURED freeze—the schedule, where `frozenAt` is the stamp—and `DayDef.scoring?: 'competitive' | 'ceremonial'` is the Day's Scoring Policy. Both are OPTIONAL, because no doc written before ADR 0011 carries either, and both are resolved on READ rather than read directly: `scoringForDay` (`src/game/scoring.ts`) falls back to the closing-pool derivation and `standingsFreezeAtFor` (`src/game/logic.ts`) to the first ceremonial Day's `unlockAt`. `eventConverter` fills both, but the RESOLVERS are the contract—several data paths hydrate raw documents no converter has touched, the same reason `normalizePool` exists.

## Acceptance criteria

- **Given** `finaleTimes.lastCallAt` has arrived (20:00 on Day 9 in the standard shape; earlier, relative to the close, when #784's same-date fallback applies), **when** the scheduled trigger fires, **then** a last-call Moment posts naming the current leader and their margin. (Test: last-call-copy.)
- **Given** the Event's Standings Freeze, **when** the last-call Moment's freeze phrase is built, **then** it quotes that ACTUAL instant formatted in the Event's timezone (not a hardcoded 8 a.m.), and the client's ban-aware reconstruction quotes the SAME phrase from the persisted Moment rather than an independently formatted one. (Test: freeze-phrase, #800.)
- **Given** the Event's Standings Freeze has arrived (08:00 on Day 10 in the standard shape, where it is the ceremonial Day's own `unlockAt`), **when** the scheduled trigger fires, **then** `frozenAt` is set, the closing Day unlocks, and a podium Moment posts with the champion, Event-wide First to BINGO, and ten daily honors. (Test: podium-payload.)
- **Given** an Event whose FINAL Day is competitive and which states its own `standingsFreezeAt`, **when** the beats are resolved, **then** the finale still runs, that Day's marks count right up to the configured instant, the podium files under the last Day, and the last-call copy quotes the configured freeze rather than any Day's unlock. (Test: competitive-close.)
- **Given** the Event has ended (`frozenAt` set) and the finale Day is unlocked, **when** a Player opens the app, **then** that Day (podium included) is the default view AND the podium actually mounts there; before the freeze it is never pinned. (Test: default-view-pin.)
- **Given** the podium, **then** its Event-wide First to BINGO never credits a Tutorial Day's mark. (Test: tutorial-exclusion.)
- **Given** the podium, **then** the champion/standings are computed EXCLUDING every ceremonial Day, and every first-bingo instant AFTER the freeze is ignored, so a post-freeze goodbye mark never changes the podium—neither the standings nor the First to BINGO. (Test: ceremonial-exclusion + freeze-cutoff.)
- **Given** ONE fixture schedule and roster, **when** both `buildPodium` and `buildPodiumPayload` compute it, **then** they name the same champion and the same First to BINGO—on the cruise shape, a competitive-curated-pool shape, a competitive-close shape, and a schedule with no ceremonial Day. (Test: podium-parity.)
- **Given** an Event doc carrying neither `scoring` nor `standingsFreezeAt` (both live Events), **when** it is read, **then** the ceremonial set and the freeze instant are exactly what the pool-scanning code produced. (Test: legacy-byte-identical.)
- **Given** the event doc, **then** `frozenAt` and `standingsFreezeAt` are admin/Function-writable only, never client-writable directly by a Player. `standingsFreezeAt` must be a finite POSITIVE number, may only ever be written into the FUTURE, may not be deleted once present, and is locked to its exact value once its cutoff has passed. Adding it to a legacy Event that carried no explicit value is also denied once the resolved first ceremonial-Day boundary has passed, even when later competitive Days remain future—every one of those is a boundary crossing that would freeze a refreshed client while a cached one stays live, or the reverse. A Day's `scoring` must be `competitive` or `ceremonial` when present, and is locked once that Day unlocks. (Test: rules.)

## Test coverage

- `tests/functions/d15-finale.test.ts` (functions layer, `vitest.functions.config.ts`)—`lastCallStandingsCopy` names the correct leader + margin from a fixture player set and degrades on a tie/empty board; `freezePhraseForUnlock` covers on-the-hour/off-the-hour/p.m. formatting, the missing-timezone and invalid-unlock fallbacks, and the `Europe/Rome` legacy default (#800); `normalizeTimezone` covers offset ids, GMT/UTC/Etc aliases, bare abbreviations, and unresolvable zone ids (#800 Codex P2); `buildPodiumPayload` excludes a Tutorial Day's first bingo from the Event-wide honor, excludes the closing Day from the champion totals, and includes all ten daily honors when present.
- `tests/functions/d15-scheduler-unlock.test.ts`—`runFinaleBeats` posts a last-call Moment whose `line` and `lastCall.freezePhrase` quote a Bodega-shaped closing Day's ACTUAL 11:00 `America/Los_Angeles` unlock, not a hardcoded 8 a.m. (#800).
- `tests/functions/lastcall-copy-parity.test.ts` (#800, cf. `finale-parity.test.ts`)—feeds identical player/freeze-phrase fixtures to `lastCallStandingsCopy` (functions) and `lastCallLineFromPlayers` (client) and asserts byte-identical output.
- `tests/functions/timezone-normalize-parity.test.ts` (#800 Codex P2)—feeds identical raw `timezone` values to both packages' `normalizeTimezone` and asserts byte-identical output.
- `src/lastCallCopy.test.ts` (Vitest unit, #800)—`lastCallLineFromPlayers` defaults to the historical freeze phrase when none is given, uses an injected one otherwise, and degrades the same way `lastCallStandingsCopy` does on a tie/empty board.
- `src/components/FarewellPodium.test.tsx` (RTL/jsdom)—renders champion, Event-wide First to BINGO, and ten daily-honor rows from a fixture payload, above the goodbye banner mount point.
- `src/data/d15-finale.test.ts` (Vitest unit)—`finalePinIndex` pins only once `frozenAt` is set and the target Day is unlocked, never before, and falls back to the last Day when no Day is ceremonial; `buildPodium` picks the champion, excludes the ceremonial Days, and excludes tutorial Days from the Event-wide First to BINGO.
- `src/game/scoring-policy.test.ts` (Vitest unit, ADR 0011)—`scoringForDay`'s stated-beats-pool resolution and its malformed-value fallback direction; `ceremonialDayIndexSet` as a SET; `standingsFreezeAtFor`'s configured-wins/derive-fallback and its rejection of a non-positive stored instant; and the legacy regression pin—the seeded ten-Day schedule and a legacy-spelling (`embark`/`farewell`) Event doc both resolve to the same ceremonial set and freeze instant as before, with `scoring` the only field the converter adds.
- `tests/functions/finale-parity.test.ts` (functions layer)—the client/functions mirror guard: identical `scoringForDay` resolution, identical ceremonial sets, and identical podium champion + First to BINGO over one fixture roster across four schedule shapes. Intended to FAIL if either package moves alone.
- `tests/rules/d15-finale.test.ts` (rules emulator)—`EventDoc.frozenAt` and `EventDoc.standingsFreezeAt` are writable by an admin/Function but rejected for a non-admin Player; a non-number `standingsFreezeAt` is rejected even from an admin; paired ten-Day cases prove adding an explicit freeze is denied after an early ceremonial boundary and still allowed before it without exhausting the rules-expression budget.
