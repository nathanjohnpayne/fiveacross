# Resolving the Event from the hostname at startup (`event-resolution`)

Implements the consuming half of [ADR 0009](../docs/adr/0009-event-resolved-from-hostname.md); `specs/hostnames-lookup.md` owns the collection and its rules. A multi-Event build decides which Event it is serving from `window.location.hostname` **before first paint**, because every Firestore path derives from `EVENT_ID`—mounting first and resolving later would start listeners against the wrong Event and then swap it underneath them.

## Glossary

**Resolution**—the answer to "which Event is this address?", always one of `{ kind: 'event', … }` or `{ kind: 'not-found', hostname, reason }`. Never an exception: not-found is a state the app draws. *Avoid:* lookup result, route match.

**Edition brand**—the wordmark, the platform **endorsement byline** under it, the one-line description and the offline note the signed-out gate shows, plus the **chrome identity**: the document title and the PWA names (`src/editions.ts`). Keyed by the Edition the hostname resolved to. *Avoid:* theme (that is a look, not an identity).

**Chrome identity**—the Edition's name where the browser shows it rather than the page does: `<title>` (tab, bookmark, share-sheet), `apple-mobile-web-app-title` (iOS home-screen label) and the PWA manifest's `name` / `short_name` / `description` (Android install prompt and home-screen label). Bound at two different times—see the contract below. *Avoid:* branding (too broad—that includes the in-page wordmark, which binds at render).

## Contract

- `src/eventResolution.ts` holds the whole decision table as a pure function with injected `fetchDoc`, `storage`, `now` and `delay`, so every branch is testable without a network, a browser or an emulator. `src/data/hostnames.ts` is the only part that touches Firestore.
- **Order of resolution**, and why each step precedes the next:
  1. **Non-empty `VITE_EVENT_ID` ⇒ answer immediately, no network.** A non-empty value means the bundle serves exactly one Event, so consulting the lookup and discarding the answer would be incoherent—and since resolution gates first paint, it would cost that build a round trip, or the full timeout on captive Wi-Fi. An empty value selects hostname resolution.
  2. **Fresh cache hit ⇒ resolve with no network.** This is what makes offline cold boot work (ADR 0006) and keeps first paint off the network's critical path.
  3. **Miss or stale ⇒ one server read, hard-bounded by `timeoutMs`.** An unbounded pre-paint read is the blank-screen failure class this repo has shipped three fixes for, so the race is load-bearing rather than defensive.
  4. **Revalidation failed ⇒ serve a stale-but-active entry** rather than a not-found. An expired mapping beats a dead app when the network is simply gone.
- **The Five Across production target is the shared router origin, not a Bodega-only bundle.** The `fiveacross` target continues to build for the `fiveacross` Firebase project and to publish its Hosting origin at `fiveacross.web.app`, which is the Worker's `ORIGIN_HOST`; it does not introduce a second Hosting site. Its target environment must define `VITE_EVENT_ID` as the exact empty string. The key remains required so an incomplete target file cannot inherit an ambient Event id, and target validation must reject every non-empty value. With that mode switch empty, `VITE_EDITION` and `VITE_ADULT_CONTENT` are not routing inputs: each serving hostname's active `hostnames/{host}` document supplies its Event, Edition and adult-content posture before mount. The target registry separately pins `vacay` as the static fallback Edition for browser chrome that cannot yet be rewritten per hostname, plus `https://auth.fiveacross.app` as the one central sign-in origin every newly resolved wildcard host uses; these are trusted target metadata, not Event-specific routing inputs. The legacy `gaycruisebingo` target remains single-Event and keeps its non-empty Event id.
- **Changing the origin bundle is a Worker cutover prerequisite, not a route attachment.** Merging or deploying this contract does not authorize uncommenting the wildcard routes. Before a human attaches them, the executable production-origin integration seam (`scripts/fiveacross-origin.integration.test.mjs`) must build the named `fiveacross` target through the production Vite configuration and inspect the emitted `index.html` and PWA manifest. Both retain the Vacay static fallback used by the existing Bodega direct-serving hosts, and the build must contain no baked Bodega Event id. The seam must also pass that target environment into the real `bootstrapEventResolution` startup boundary. Its fixture table covers `bodega-bay.fiveacross.app`, `bodega-bay.vacaybingo.com`, and `fiveacross.app` resolving to `bodega-bay-2026` / `vacay`, plus a second active `*.fiveacross.app` host resolving to its own non-Bodega Event / `fiveacross` Edition with `adultContent: true`. Every row asserts the returned Event id and the installed Firebase `EVENT_ID`, card-cache Event id, active Edition and adult-content posture; the adult fixture additionally proves the live `true` posture has settled before mount and that the registered production environment selects ADR 0010's handoff through `auth.fiveacross.app` without an exact-host source edit. This is the production-shaped cross-layer proof that the unit seams alone cannot provide. The other cutover gates in `worker/README.md` remain independent.
- **The read must reach the server.** `getDocFromServer`, never `getDoc`: the latter may answer from Firestore's own cache, so an offline client would read a stale mapping, treat it as successful revalidation, and restamp the entry for another full TTL—a bound that renews itself is not a bound. The call throws when the server is unreachable, which is precisely how step 4 is entered, and step 4 does **not** restamp.
- **`status` must be explicit.** Only `'active'` is servable. A missing or unrecognised `status` is not treated as active on either the network or the cache path: defaulting it would let a half-written routing document publish an Event before the record opts in.
- **Cache shape.** `localStorage`, keyed by hostname (not Slug—two hostnames can resolve to one Event, and a shared key would let an alias serve the canonical's cached Edition on the wrong origin). Envelope carries a schema version and `fetchedAt`; a version mismatch, corrupt JSON or a shape-drifted document all read as a MISS, never as coerced data. TTL is 12 hours. A mapping that is removed or goes inactive has its entry **dropped**, not expired. Storage that throws on access (private mode, embedded webviews) degrades to "no cache", never to a failed boot.
- **`src/main.tsx` awaits resolution before mounting.** On `not-found` it renders `EventNotFound`—which is deliberately dependency-free (no auth, no Firestore, no router, no theme), since it renders when we have decided the app is not safe to mount. The `.catch` around the bootstrap is a hard blank-screen guard: resolution is written never to throw, but this is the one path where an unexpected throw would render nothing at all. What it renders splits on the build mode (`shouldMountOnBootstrapFailure`, `src/eventResolution.ts`): an env-pinned build mounts, since its baked `EVENT_ID` is the correct Event and a blank page is strictly worse; a hostname-resolved build fails CLOSED to the `unreachable` screen, since its pre-resolution `EVENT_ID` is the legacy fallback and mounting would serve the legacy Event on an arbitrary hostname with the auth gate skipped.
- **The analytics disclosure survives the not-found branch.** `ConsentNotice` renders beside `EventNotFound`. GA4 loads on `firebase.ts` import and PostHog initialises at module scope, both before resolution, so collection has already begun for a visitor who never reaches the app—and an unknown wildcard host is exactly where a first-time visitor lands.
- **An Event is not mounted on an origin where sign-in cannot COMPLETE.** The gate asks `resolveSignInStrategy` for the route that the Sign in button will use. That resolver consults `isSignInReachableOnHost` (`src/auth-domain.ts`) first, preserving direct sign-in on every exact registered first-party host, on the build-time same-origin pin, on `gaycruisebingo.web.app` through its documented `firebaseapp.com` redirect, and on local/loopback development origins. An active wildcard host outside that direct set is no longer rejected merely because it lacks its own OAuth callback: in the default `handoff` mode it mounts through ADR 0010's configured central origin. It fails before mount only when the selected route itself is unusable—`same_origin` on an unregistered host, an invalid mode, or a missing/malformed central origin. The exact-host set is therefore a direct-route override, not the source of truth for whether a newly provisioned Event can sign in.
- **The resolved Edition brands the pre-auth shell—every surface of it.** `bootstrapEventResolution` installs it via `setActiveEdition`, and each of the three screens built on the `.signin` shell reads `editionBrand()`: the signed-out gate and the `DealError` retry panel (`SignIn`), and the crash panel (`ErrorBoundary`). An unknown or absent Edition falls back to the legacy `gcb` brand—degrading to the shipped experience, never to a blank wordmark. The boundary is the one place where this brand read has to justify itself, because its own contract is to depend on nothing the crash could have broken: `editionBrand()` is a synchronous table lookup with a total fallback—no hook, no context, no I/O, no throwing input—and `src/editions.ts` already sits in the boot graph, so it adds no failure mode that would not already have prevented the boundary from existing.
- **An Edition of the platform signs its lockup, and that signature is not part of its name.** `wordmarkByline` is optional on the brand table and carries the platform endorsement (`BY FIVE ACROSS`) under the wordmark on the two surfaces that draw a full lockup: the signed-out gate (`SignIn`) and the in-app header (`Nav`). It is carried by Editions **of** the platform—Vacay since #647, Gay Cruise Bingo since #688—and omitted by `fiveacross`, which IS the platform and would be endorsing itself. The distinction the field has to hold is endorsement versus rename: the byline is a SIBLING of the gate's `h1`, never inside it, so `wordmark` and the chrome identity (`documentTitle`, `appName`, `appShortName`) stay exactly the product's name—which is also what the production synthetic waits on. The two minimal `.signin` surfaces deliberately go without the byline on every Edition, and (#881) they no longer share one offline message either: the crash panel carries the wordmark and its total-failure fallback (`crashFallbackNote ?? offlineNote`—the ROUTINE dead-zone promise is the wrong claim for a screen that exists because the app just crashed), while the `DealError` panel carries the wordmark, the failure `message` and Retry, and NO offline note at all—no card was dealt yet on that screen, so "your card keeps working offline" has nothing to refer to. Depending on as little as possible no longer means depending on the SAME field.
- **The Edition also brands the browser chrome, and it binds at two different times.** A **single-Event** build knows its Edition from `VITE_EDITION` before it is built, so `vite.config.ts` bakes the chrome identity in: `brandHtmlIdentity` substitutes the `index.html` placeholders and the same brand supplies the PWA manifest fields. A hostname-resolved target instead ignores `VITE_EDITION` and may carry an explicit static fallback Edition in trusted target-registry metadata. The Five Across target uses `vacay`: its direct-serving Bodega hosts therefore keep their current pre-JavaScript and install identity while runtime resolution remains generic. Without that explicit metadata, `buildTimeEdition` returns the default Edition whenever `VITE_EVENT_ID` is empty, so a stale ambient `VITE_EDITION` still cannot brand a shared bundle. After startup, `bootstrapEventResolution` calls `applyEditionDocumentIdentity` after `setActiveEdition` to correct the document title and iOS label for the resolved host. The manifest is deliberately not patched at runtime: `name` / `short_name` are read from the manifest FILE at install time. Therefore #546's edge rewrite remains a prerequisite before any non-Vacay Edition hostname is attached to a wildcard route; #851 does not claim that static identity is generic yet. An unrecognised `index.html` placeholder FAILS the build rather than shipping as literal text.
- **`cardCache` is told the Event id separately.** It keeps its own copy on purpose, to stay out of the Firebase import graph; missing this call would silently key the offline card cache to a different Event than the data it caches.

## Acceptance criteria

- **Given** a build with a non-empty `VITE_EVENT_ID`, **when** it starts, **then** it resolves to that Event and performs no lookup at all.
- **Given** the named `fiveacross` production target, **when** its environment is validated, **then** `VITE_EVENT_ID` is present and empty, a non-empty target value is rejected, and a stale ambient Event id cannot reach Vite.
- **Given** the shared Five Across bundle on any active serving hostname, **when** startup completes, **then** the installed Event id is the id in that hostname's routing document; specifically, all existing Bodega serving hosts install Bodega and a second Event hostname installs the second Event.
- **Given** that second Event hostname and the registered Five Across target environment, **when** sign-in is resolved, **then** it selects the central handoff without an exact-host source edit or Event-specific build setting.
- **Given** #851's implementation lands, **then** `worker/README.md` removes or replaces the #851 origin-bundle prerequisite, retains the independent #852 and #888 gates, and names #546 as the remaining static-identity gate before a non-Vacay Edition hostname is attached; `docs/app/deploy-targets.md` describes `fiveacross` as the generic hostname-resolved origin instead of a Bodega-pinned runtime target, including explicit pre-cutover verification of every Bodega serving host; and `docs/adr/0009-event-resolved-from-hostname.md`, `docs/app/README.md`, `specs/x-multi-event-schema.md`, plus affected runtime comments consistently name a **non-empty** `VITE_EVENT_ID` as the single-Event switch and an empty value as hostname resolution.
- **Given** the shared target's production output, **when** its built `index.html` and PWA manifest are inspected, **then** they retain Vacay's static identity for the existing Bodega hosts and do not contain a baked Bodega Event id.
- **Given** a fresh cached mapping, **when** the app starts, **then** it resolves from cache with no network read.
- **Given** a stale cached mapping and a reachable server, **when** the app starts, **then** it revalidates and follows the current mapping.
- **Given** a stale cached mapping and an unreachable server, **when** the app starts, **then** the stale mapping still serves and is **not** restamped.
- **Given** a hostname whose mapping was removed or set inactive, **when** the app starts, **then** it renders not-found and the cached entry is dropped.
- **Given** a routing document with no explicit `active` status, **when** it is read from either the network or the cache, **then** it is not servable.
- **Given** a hostname lookup, **when** the seam reads it, **then** the read is a server read and never satisfiable from Firestore's cache.
- **Given** a hung lookup, **when** `timeoutMs` elapses, **then** resolution completes as not-found (or stale cache) rather than blocking paint.
- **Given** a resolved Edition, **when** the signed-out gate renders, **then** its wordmark, description and offline note are that Edition's—and no other Edition's itinerary or copy appears.
- **Given** an Edition of the platform (`gcb`, `vacay`), **when** the signed-out gate or the in-app header renders, **then** the endorsement byline appears under the wordmark and outside the `h1`; **given** `fiveacross`, **then** no byline is drawn.
- **Given** any Edition, **then** the endorsement never appears in that Edition's `wordmark`, `documentTitle`, `appName` or `appShortName`—the byline is a signature on the lockup, not part of the product's name.
- **Given** a resolved Edition, **when** the React tree crashes and the boundary renders its recovery panel, **then** that panel carries the same Edition's wordmark and offline note—a crash is not an excuse to show a player a different product's name.
- **Given** a single-Event build for an Edition, **when** it is built, **then** the served `index.html` and PWA manifest carry that Edition's chrome identity, and no placeholder survives.
- **Given** a build with an empty `VITE_EVENT_ID` and no explicit target fallback but a leftover `VITE_EDITION`, **when** it is built, **then** the baked chrome identity is the default Edition's, not the leftover one's.
- **Given** the hostname-resolved Five Across target's explicit Vacay fallback, **when** it is built, **then** the fallback brands only static chrome; a live hostname document still installs its own Event, Edition and adult-content posture before mount.
- **Given** a hostname-resolved build, **when** the Edition is installed, **then** the document title and the iOS home-screen label become that Edition's.
- **Given** a not-found hostname, **when** that state renders, **then** the 18+ analytics disclosure renders with it.
- **Given** an Event that resolves on an origin where `isSignInReachableOnHost` is false—the resolved `authDomain` is a different host, the origin has no documented handoff, and it is not a local/loopback origin—**when** the app boots, **then** it renders the `auth-unconfigured` state rather than mounting sign-in.
- **Given** the same build served on `gaycruisebingo.web.app` or on a local/emulator origin (`localhost`, `127.0.0.1`), **when** the app boots, **then** it mounts: web.app so the `firebaseapp.com` handoff can run before any auth transaction, local origins so the dev/emulator popup path stays reachable.
- **Given** an Edition-less resolution (the env short-circuit), **when** it is installed, **then** the Edition seeded from `VITE_EDITION` is left intact rather than reset to the default.
- **Given** the `auth-unconfigured` state on a `*.vercel.app` hostname—by construction a per-deployment preview host, since every registered Vercel host is in `FIRST_PARTY_AUTH_HOSTS`—**when** it renders, **then** it adds a developer note naming the stable preview alias and `docs/app/preview-deploys.md`, leaving the player-facing copy unchanged; no other hostname and no other reason shows it.

## Test coverage

- `src/eventResolution.test.ts`—the decision table and the cache envelope against injected storage/clock/fetch: cache key, round-trip, TTL boundary, version drift, corrupt JSON, throwing storage, explicit-status rule, and every ordering branch above including the hung-fetch timeout (without the race the test would never settle).
- `src/data/hostnames.test.ts`—the Firestore seam: `getDocFromServer` is called and `getDoc` is not, hostname lowercasing, malformed documents reading as null, a server failure propagating as a throw, and `bootstrapEventResolution` installing the Event id, the card-cache id, the Edition and the document title together.
- `scripts/build-target.test.mjs`—the production-target seam: `fiveacross` requires an explicitly empty `VITE_EVENT_ID`, rejects a Bodega-pinned target file, overwrites a stale ambient Event id with the empty selected value, pins the central auth origin, and supplies the trusted Vacay static fallback independently of `VITE_EDITION`.
- `scripts/fiveacross-origin.integration.test.mjs`—the production-origin integration seam: builds and inspects the registered `fiveacross` production output, then composes its environment with the real startup bootstrap and table-tests the three existing Bodega hosts plus an adult second Event host, asserting resolution and all four installed identities (Firebase, card cache, Edition, adult-content posture) plus the second host's central handoff route.
- `src/components/EventNotFound.test.tsx`—the `auth-unconfigured` screen's audience split: the preview-host developer note appears on a `*.vercel.app` hostname, is absent on a real address, and is absent for the `missing` / `inactive` / `unreachable` reasons.
- `src/editions.test.ts`—the brand table: legacy default, Vacay override, fallback for unknown/absent, no empty strings, and no cruise vocabulary in a non-cruise Edition. Plus the chrome identity: the legacy Edition's four strings pinned verbatim, every `short_name` inside Android's truncation budget, `brandHtmlIdentity` substituting and escaping, its throw on an unrecognised placeholder, a run against the REAL `index.html` for every Edition, and `applyEditionDocumentIdentity` retitling the DOM.
- `src/components/signin-edition-brand.test.tsx`—that the gate and the `DealError` panel actually read the brand rather than holding their own strings.
- The endorsement byline (#688): `src/editions.test.ts` asserts the endorsed set as an exhaustive partition over the Editions—so a fourth cannot be added without deciding its side of the line—and that the endorsement stays out of every name field. `src/components/nav-edition-brand.test.tsx` covers the header (drawn for both Editions of the platform, absent for `fiveacross`, and never folded into `.brand-wordmark`), and `src/components/event-postcard.test.tsx` covers the gate, including that GCB takes the byline WITHOUT taking Vacay's Join voice, and that neither Edition's byline reaches the `h1`.
- `src/components/ErrorBoundary.test.tsx`—the third `.signin` surface: the crashed boundary renders the resolved Edition's wordmark and its total-failure fallback (`crashFallbackNote`, falling back to the routine `offlineNote` for an Edition with no printed-card tradition of its own), with no cruise copy surviving on a non-cruise Edition, and falls back to the legacy brand on an unknown one.
- `src/auth-domain.test.ts`—the auth-readiness and reachability predicates: first-party hosts, the same-origin pin, an unconfigured wildcard host, agreement with `resolveAuthDomain` by construction, the web.app handoff exception, and the local/emulator exemption.
