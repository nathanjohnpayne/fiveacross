# Repository Overview

This repository is **Five Across**—a live, phone-first social bingo platform (PWA) for a group sharing one occasion. Players sign in, get a randomized 5×5 Day Card of things that might happen there, and mark them off as they do, with a shared Feed, a leaderboard, per-Day Themes, PWA install, and Honor-mode Marks that queue durably offline and sync on reconnect. A tab whose Firestore queue reaches the permanent `b815` latch can recover through one guarded reload without clearing its persisted data; an uncontrolled page waits for an origin-reachability proof first ([`w0-offline-persistence`](../../specs/w0-offline-persistence.md)). Proof media needs signal, and `proof_required` / `admin_confirmed` cannot complete a Mark offline at all—`ProofSheet` enables the bare pledge only in Honor mode and `attachProof` is transaction-plus-upload, so it is online-only ([ADR 0006](../adr/0006-offline-resilience.md)). Printed cards are the Gay Cruise Bingo Edition's own fallback for total failure (`gcb.crashFallbackNote`, read by `ErrorBoundary.tsx`—`gcb.offlineNote` is the separate routine-dead-zone promise, #881), not a platform feature.

One Brand wears an **Edition** per class of occasion and runs one **Event** per occasion, each addressed by its own hostname and resolved pre-auth ([ADR 0009](../adr/0009-event-resolved-from-hostname.md)). Two Editions are live: Gay Cruise Bingo (`gaycruisebingo.com`, the completed `med-2026` sailing) and Vacay Bingo (`bodega-bay.fiveacross.app`, the canonical host per #599 as amended—`bodega-bay.vacaybingo.com` stays live as an alternate serving host). They are backed by two production Firebase projects, giving the Editions separate Firebase resources and deploy targets from one source tree. That split is **not** cohort isolation and must not be described as one—a signed-in account can still reach either app until membership-scoped rules land ([ADR 0008](../adr/0008-five-across-second-firebase-project.md)). The product overview is in [`README.md`](../../README.md), the Brand/Edition model in [`BRAND.md`](../../BRAND.md), and the domain vocabulary in [`CONTEXT.md`](../../CONTEXT.md)—which is also the neutral vocabulary the prose tree is converging on, so prefer Event over cruise or sailing.

## Stack

Vite + React 19 + TypeScript (strict) · Firebase (Auth · Firestore · Storage · Hosting · Analytics) · `vite-plugin-pwa` with a custom service worker · Cloud Functions · Cloud Scheduler · PostHog and GA4 · Cloudflare DNS and edge redirects. Player stats stay client-authoritative and the leaderboard is a client-side sort ([ADR 0001](../adr/0001-honor-system-trust-model.md)); the Functions package carries only what needs a server—scheduled Day unlocks and finale computation, threshold hiding, Vision-flag hiding, the three-trigger adult-posture derivation/reconciliation invariant (ADR [0012](../adr/0012-server-derived-adult-content-posture.md)), bounded legacy-marker identity normalization, moderation email, and bug-report intake. Cloud Vision proof moderation sits behind the `ENABLE_VISION_MODERATION` deploy-time gate, and because the `_thumb.jpg` write lives inside that same handler, a default deployment produces **neither** Vision scanning nor server-side proof thumbnails. Its consumer is not gated with it: `hideProofOnVisionFlag` ([`specs/cloud-vision-moderation.md`](../../specs/cloud-vision-moderation.md)) deploys unconditionally and hides an extreme/illegal `visionFlag`, so with the scanner off it simply never fires—it never auto-hides for raciness, and never gates posting.

## Agent role

Build and maintain the Five Across platform—game logic, Event and Edition resolution, Firebase data/rules, auth, Themes, and the proof/moderation system—keeping `specs/`, `docs/`, and tests in step with behavior. Ship changes via branch + PR under the review policy (see [`AGENTS.md`](../../AGENTS.md) § Code Review Policy).

## Relationship to mergepath

This repo was scaffolded from—and tracks—the **mergepath** template, the canonical implementation of the AI Agent Tooling Standard for this account. It therefore carries mergepath's governance and tooling: the review policy ([`REVIEW_POLICY.md`](../../REVIEW_POLICY.md)), the 1Password-backed deploy tooling ([`DEPLOYMENT.md`](../../DEPLOYMENT.md)), and this `docs/agents/` set. Five Across is a **consumer** of that template, not the template hub—the hub-only propagation/bootstrap docs alongside this one (e.g. [`propagation-ordering.md`](propagation-ordering.md), [`templated-propagation.md`](templated-propagation.md), [`bootstrap-runbook.md`](bootstrap-runbook.md)) describe machinery that runs in mergepath, not here.

Private profiles, Admin data and block read listeners use the isolated memory client described in `specs/private-cache-isolation.md`. Preserve the staged attended legacy-cache recovery boundary, queued gameplay Marks and durable block batches; only already-confirmed same-account/Event block sets carry shared Feed/Tally rendering into an offline session. Cold offline reloads show explicit reconnect states under ADR 0006. Gameplay bootstrap waits through scheduled private-bridge retries under one five-second readiness bound; exhaustion and timeout retain explicit Retry, and server denial or actor/lease retirement cannot authorize a deal. Gameplay connection Retry restarts an unavailable current-actor bridge or an explicitly identified connection-class private SDK read failure with a still-current captured UID/client/generation and caller Event/attempt (#1732). Successful SDK reads and permanent authority rejection disarm timeout provenance; terminal publication retires saved Retry callbacks before further bootstrap or replacement; transaction writes, permanent denial and unrelated gameplay failures do not qualify. Preserve a healthy private app, captured leases and confirmed block readiness across unrelated deal retries. Active same-UID Auth refresh copies have a five-second deadline; timely copies preserve that client, while a current timeout retires it and starts independent bounded recovery with the latest subject. Cancel owned copy timers on completion/retirement and fence uncancelled late SDK results. Initial bootstrap-copy hangs remain a separate path. Reciprocal block-read retry budgets renew only on a current committed, non-pending server answer; preserve bounded unresolved episodes, terminal denial and scope fences.

Admin settings feedback follows [`admin-async-feedback`](../../specs/admin-async-feedback.md): retain committed private Event values during pending writes, catch settings/Day-theme rejections inline, preserve force-adult confirmation ownership, and allow an identical failed Easy mix release to retry without serializing rapid keyboard releases. A latest failed Easy mix fallback may follow later committed props during focus only while no newer draft/request owns the display; retain its alert and the layout-phase committed reference, and end recovery on input, request, blur or scope retirement (#1713). Keep busy settings and Day-theme controls focusable with guarded native activation; retain the threshold floor, Day lock and modal safety disabling. Retired private scopes must not receive old action feedback.

When the recovery query key is absent, the credential-safe entry starts loading the application graph without first awaiting the recovery-navigation import. Preserve deferred recovery selection and credential capture before application or recovery imports.

Proof media (#1410): preserve the network-only/no-store policy and legacy proof-cache and cache-scoped Workbox expiration-record purge. Never clear Firestore IndexedDB or queued offline Marks as part of a media-cache migration. Source verification does not establish deployment or recall previously cached/downloaded copies; token/moderation policy remains owner-decided under #806/#1356.

Proof-media token operations reuse `functions/src/proofMediaTokens.ts` (#1534): conditional metadata-only stripping, the existing private/no-store policy and transactional resumable progress. Retry one operation with its original sweep ID; a later revocation needs a new ID. No trigger or production sweep is implied by this primitive; see `specs/proof-media-token-revocation.md`.

Event Invitation callables (#803) bind the owner-accepted policy in `functions/src/eventInvitations.ts` through `eventInvitationCallables.ts` and the Admin transaction adapter. They grant member-only single-use Invitations for 24 hours, require live Admin plus active Membership authority, atomically revoke provenance-matching grants, and return rolling-window retry times. Existing Admin Membership seeding and the operator path remain #805 rollout prerequisites; see [`event-invitations`](../../specs/event-invitations.md).

Proof-media holds are reconciled from current Proof snapshots by `functions/src/proofMediaHold.ts` and the retrying Proof-write trigger; a minute scheduler drains server-only durable lease repairs. `specs/proof-media-hold.md` defines full-precision source ordering and the exported pre-hold/deadline contract. Storage Rules reserve the three hold metadata keys for server writers, and every thumbnail save reconciles current Proof state. This module does not cut existing hide paths over to leases; that staging rollout remains #1356.
